# 실험 1 결과 — 정지 자세 중력 방향

## 실험 개요

로봇을 완전 정지(엎드림)시킨 상태에서, 네 개의 IMU 소스가 각각 "아래(중력)"를
어떻게 감지하는지 3분간 실시간 기록하고 비교한다.

- **날짜:** 2026-08-18
- **자세:** 엎드림 정지 (몸통 앞쪽이 지지대 때문에 약 5° 들려 있음 — 아래 "자세 보정" 참고)
- **기록:** `exp1_gravity_record.py`, 3분(180초), 실행 즉시 CSV 기록
- **원본 CSV:** `exp1_gravity_20260818_101320.csv`

### 기록 소스

| 라벨 | 토픽 | 정체 | 주기 |
|---|---|---|---|
| L1 | `/utlidar/imu` | L1 원본 (자이로+가속도 모두 L1) | 250 Hz |
| body | `/lowstate` | 몸통 IMU 원본 | 500 Hz |
| body_lf | `/lf/lowstate` | 몸통 IMU 저주파 | 20 Hz |
| fix | `/l1_imu_fixed` | **L1 자이로 + 몸통 가속도를 R_LB로 회전한 합성** | 250 Hz |

> **fix 출력값의 정체 (코드 확인):**
> - 각속도(angular_velocity) = `/utlidar/imu`(L1) 그대로 (L1 자이로는 정상)
> - 가속도(linear_acceleration) = `/lowstate`(몸통) 가속도를 `R_LB`로 회전 + `ACC_SCALE` 곱
> - 즉 `a_fix = R_LB · (a_body · ACC_SCALE)`

## 사용한 수식

### 기호 설명 (수식에 쓰인 미지수)

| 기호 | 의미 | 비고 |
|---|---|---|
| `a` | 가속도 벡터 (aₓ, a_y, a_z) | m/s² |
| `aₓ, a_y, a_z` | 가속도의 x·y·z 성분 | |
| `\|a\|` | 가속도 벡터의 크기(magnitude) | √(aₓ²+a_y²+a_z²) |
| `g` | 표준중력 = 9.807 | m/s² |
| `θ` (theta) | 두 벡터 사이 각도 | 도(°) |
| `a · b` | 두 벡터의 내적(dot product) | 스칼라값 |
| `R_LB` | base_link(몸통) → LiDAR 프레임 회전행렬 | go2_calib.py 확정값 |
| `a_body` | 몸통 IMU가 잰 가속도 | base_link 프레임 |
| `ACC_SCALE` | 몸통 가속도계 크기 보정 계수 | 9.807 / 9.465 = 1.03614 |
| `det(R)` | 행렬식(determinant) | 회전행렬이면 +1 |

> **참고:** 이 실험에서 각 소스의 "정상 기준값"은 `R_LB · (a_body · ACC_SCALE)`이다.
> 즉 몸통 가속도를 스케일 보정하고 LiDAR 프레임으로 회전한 값. fix·L1이 정상이라면
> 이 값과 같아야 한다.

### ① 중력 크기 (magnitude)

각 IMU가 정지 상태에서 재는 가속도 벡터 `a = (aₓ, a_y, a_z)`의 크기.
정지 상태에서는 중력 반력만 재므로, 표준중력 `g = 9.807 m/s²`에 가까워야 한다.

```
|a| = √(aₓ² + a_y² + a_z²)
```

크기 오차(%) = `(|a| − 9.807) / 9.807 × 100`

### ② 중력 방향 오차 — "정상이라면 나와야 할 값"과의 각도

두 벡터 `a`, `b` 사이의 각도는 내적으로 구한다.

```
              a · b
cos θ = ─────────────────
          |a| · |b|

θ = arccos(cos θ)   [도]
```

**주의 — 이 실험에서 배운 것:**
처음에는 "수직 축(0,0,+z)에서 벗어난 각"으로 쟀는데, 이 방식은
**프레임(좌표 규약)이 다른 센서를 잘못 판정**한다. fix는 설계상 z 부호가
body와 반대(아래 R_LB 참고)여서, 수직 기준으로는 159°(거의 반대)로 나와
"고장"처럼 보였다. 실제로는 정상이었다.

→ 올바른 비교: **"그 센서가 정상이었다면 나와야 할 값"과의 각도**를 잰다.
   fix·L1의 정상 기준값은 `R_LB · (a_body · ACC_SCALE)` 이다.

### ③ fix 검증 — R_LB 회전 행렬

`R_LB`는 base_link(몸통) → LiDAR 프레임 회전 행렬.

```
        ⎡ +0.523029  −0.838576  +0.152420 ⎤
R_LB =  ⎢ −0.810712  −0.544668  −0.214668 ⎥
        ⎣ +0.263034  −0.011292  −0.964721 ⎦
```

- **det(R_LB) = +1.0** → 올바른 회전 행렬 (반사/뒤집힘 아님).
  det가 −1이면 좌우 손 좌표계 혼용(어떤 회전으로도 정렬 불가)인데, +1이므로 정상.
- 3번째 행의 `−0.964721`(≈ −1)이 몸통의 +z를 LiDAR 프레임의 −z로 보낸다.
  → **fix의 z가 음수인 것은 버그가 아니라 R_LB 설계** (L1 프레임 z가 몸통과 반대).

### ④ 스케일 보정 (ACC_SCALE)

몸통 가속도계 정지 크기가 9.465(표준 대비 −3.49%)라서, 보정 계수를 곱한다.

```
ACC_SCALE = 9.807 / 9.465 = 1.03614
```

## 결과

### 정지 평균 가속도 벡터

| source | aₓ | a_y | a_z | mag (\|a\|) |
|---|---|---|---|---|
| L1 | +4.042 | −0.001 | +9.806 | 10.607 |
| body | +0.864 | +0.141 | +9.448 | 9.489 |
| body_lf | +0.863 | +0.141 | +9.448 | 9.488 |
| fix | +1.838 | −2.906 | −9.211 | 9.832 |

### 지표 1 — 중력 크기 정확도

| source | \|a\| | 오차 |
|---|---|---|
| L1 | 10.607 | **+8.15%** |
| body | 9.489 | −3.25% |
| **fix** | **9.832** | **+0.25%** |
| body_lf | 9.488 | −3.25% |

- fix가 가장 정확(+0.25%). body 원본의 −3.25%를 ACC_SCALE로 보정한 결과.
- L1은 크기부터 +8% 틀림.

### 지표 2 — fix가 설계대로 나오는가

```
예측 R_LB·(a_body·1.036) = (+1.838, −2.906, −9.211)
fix 실측                 = (+1.838, −2.906, −9.211)
각도차 = 0.000°   |   크기차 = 0.000 m/s²
```

→ fix는 설계값과 **완전 일치**. fix 스크립트에 오차·버그 없음.

### 지표 3 — L1 고장 정도

L1이 정상이라면 `R_LB·(a_body·1.036)`과 같아야 한다.

```
정상 기준 = (+1.838, −2.906, −9.211)
L1 실측   = (+4.042,  −0.001,  +9.806)
각도차 = 142.6°
```

→ L1은 정상값과 **142.6° 어긋남** = 심한 고장 (기존 진단과 일치).

> **주의:** L1을 "수직 축 기준"으로 재면 22°로 나오지만, 이는 잘못된 비교다.
> "정상이라면 나올 값" 기준으로 142.6°가 실제 고장 정도다.

### 자이로(각속도) 정지 평균

| source | gₓ | g_y | g_z |
|---|---|---|---|
| L1 | +0.004 | −0.001 | +0.001 |
| body | −0.010 | −0.014 | −0.002 |
| fix | +0.004 | −0.001 | +0.001 |

→ 네 소스 모두 0 근처(≤0.014 rad/s). 정지 상태 확인됨, 자이로는 전부 정상.

## 자세 보정 참고 (로봇 5° 기울어짐)

- body가 수직에서 약 5.3° 기울어 있음(aₓ=0.86). 이는 **센서 오차가 아니라
  로봇이 실제로 앞쪽이 들린 자세**(엎드림 시 배쪽 지지대로 머리가 들림)다.
- **비교에 무관:** 기울어짐은 모든 센서에 공통으로 들어가므로, 센서 간 비교에는
  영향이 없다. 실험 1은 절대 각도가 아니라 **센서 간 상대 비교**로 판단한다.

## 결론

1. **L1 가속도계는 여전히 고장** — 크기 +8.15%, 정상 대비 방향 142.6° 어긋남. 기존 진단 재확인.
2. **fix는 정지 상태에서 완벽 작동** — 크기 오차 +0.25%, 설계값과 0.000° 일치. 버그 없음.
3. **fix의 z 음수는 정상** — R_LB(det=+1) 설계에 따른 프레임 규약이지 오류 아님.
4. **body_lf = body** — 저주파 버전일 뿐 값 동일.

### 미해결 (실험 2·3에서 확인)

- 실험 1은 **정지 상태의 정적 정확도**만 검증했다. fix가 정지에서 완벽한 것은
  가속도 원천이 몸통이라 어느 정도 당연하다.
- **"움직일 때도 fix가 정확한가"**(R_LB 회전이 동적 상황에서 맞는가, 스케일이 맞는가)는
  실험 2(상관계수=동조)와 실험 3(RMSE=정확도)에서 확인해야 한다.

### 방법론적 교훈

놀라운 값(fix 159°)이 나왔을 때 지표를 그대로 믿지 않고 근원(R_LB, det)을
코드로 확인해 "지표 착오"임을 밝혔다. 지표 선택이 결론을 좌우하므로,
비교는 "절대 기준"이 아니라 "정상이라면 나올 값" 기준으로 해야 한다.

## CSV 파일 보는 법

기록 스크립트(`exp1_gravity_record.py`)는 raw 값만 저장한다. 소스별 평균·
크기·각도는 저장된 CSV를 후처리해서 계산한다. 아래 방법으로 재현할 수 있다.

### CSV 구조

```
t, source, ax, ay, az, gx, gy, gz, mag, gravity_angle_deg
```

- `t` : 기록 시작 후 경과 시간(초)
- `source` : L1 / body / body_lf / fix
- `ax, ay, az` : 가속도 (m/s²)
- `gx, gy, gz` : 각속도 (rad/s)
- `mag`, `gravity_angle_deg` : 스크립트가 미리 계산해 둔 값
  (단, `gravity_angle_deg`는 수직 기준이라 프레임이 다른 fix에는 오해를 준다 —
   위 "사용한 수식 ②" 참고. 올바른 판정은 아래 분석 코드로 다시 한다.)

### 1) 빠르게 훑어보기 (터미널)

```bash
# 첫 몇 줄
head exp1_gravity_20260818_101320.csv

# 소스별 줄 수 (샘플 수) 세기
cut -d, -f2 exp1_gravity_20260818_101320.csv | sort | uniq -c
```

### 2) 소스별 평균·크기·각도 계산 (이 실험에 실제로 쓴 분석)

아래 파이썬을 `analyze_exp1.py`로 저장하고 CSV 경로만 바꿔 실행하면
결과표가 그대로 재현된다.

```python
import csv, math, numpy as np
from collections import defaultdict

PATH = 'exp1_gravity_20260818_101320.csv'   # <- CSV 경로

rows = defaultdict(list)
with open(PATH) as f:
    for row in csv.DictReader(f):
        rows[row['source']].append(row)

def mean_vec(d):
    return np.array([np.mean([float(x[k]) for x in d]) for k in ('ax','ay','az')])

# R_LB: base_link -> LiDAR (go2_calib.py 와 동일)
R_LB = np.array([
    [+0.523029, -0.838576, +0.152420],
    [-0.810712, -0.544668, -0.214668],
    [+0.263034, -0.011292, -0.964721],
])
ACC_SCALE = 1.03614

def ang(a, b):
    c = np.dot(a, b) / (np.linalg.norm(a) * np.linalg.norm(b))
    return math.degrees(math.acos(max(-1, min(1, c))))

vecs = {s: mean_vec(rows[s]) for s in ('L1','body','body_lf','fix') if rows[s]}

# 지표 1: 중력 크기 정확도
print('== 크기 정확도 ==')
for s, v in vecs.items():
    m = np.linalg.norm(v)
    print(f'{s:8s} |a|={m:.4f}  오차 {(m-9.807)/9.807*100:+.2f}%')

# 지표 2/3: "정상이라면 나올 값"(R_LB·body) 과의 각도
pred = R_LB @ (vecs['body'] * ACC_SCALE)
print('\n정상 기준(R_LB·body) =', np.round(pred, 3))
print(f"fix 각도차 = {ang(pred, vecs['fix']):.3f}°   (0에 가까우면 fix 정상)")
print(f"L1  각도차 = {ang(pred, vecs['L1']):.2f}°   (클수록 L1 고장)")

# 자이로 정지 평균 (0 근처여야 정상)
print('\n== 자이로 정지 평균 (rad/s) ==')
for s in vecs:
    g = np.array([np.mean([float(x[k]) for x in rows[s]]) for k in ('gx','gy','gz')])
    print(f'{s:8s} ({g[0]:+.4f}, {g[1]:+.4f}, {g[2]:+.4f})')
```

### 3) 판정 기준 (요약)

| 무엇을 보나 | 계산 | 정상 판정 |
|---|---|---|
| 크기 정확도 | `\|a\|` vs 9.807 | 오차 작을수록 좋음 |
| fix 정상 여부 | fix vs `R_LB·(body·1.036)` | 각도차 ≈ 0° |
| L1 고장 정도 | L1 vs `R_LB·(body·1.036)` | 각도차 클수록 고장 |
| 정지 여부 | 자이로 평균 | 0 근처(≤0.02 rad/s) |

> 프레임이 다른 fix가 왜곡된다. 반드시 위 "정상 기준(R_LB·body)" 각도로 판정한다.
