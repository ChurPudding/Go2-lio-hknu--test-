# 실험 2 결과 — 움직임 중 상관계수 (동조)

## 실험 개요

로봇을 조종기로 직진·회전·곡선 이동시키며 세 IMU(L1, body, fix)와 오도메트리를
함께 기록하고, 각 IMU가 실제 움직임을 얼마나 "따라가는가"(패턴 동조)를
오도메트리 기준으로 채점한다.

- **날짜:** 2026-08-18
- **기록:** `exp2_motion_record.py`, 실행 즉시 CSV 기록
- **원본 CSV:** `exp2_v2.csv` (개선판)
- **동작 시퀀스(조종기):**
  정지 15초 → [1m 전진 → 정지] × 5 (가다 서다) → 정지 → 원 2바퀴(지름 40cm) → 정지

### 기록 소스

| 라벨 | 토픽 | 정체 |
|---|---|---|
| L1 | `/utlidar/imu` | L1 원본 (검증 대상) |
| body | `/lowstate` | 몸통 IMU (정상 기준) |
| fix | `/l1_imu_fixed` | L1 자이로 + 몸통 가속도를 R_LB로 회전 |
| odom | `/utlidar/robot_odom` | 채점 기준(정답지) — 위치·자세·속도 |

> **왜 "가다 서다"인가:** 상관계수는 가속도가 변하는 순간이 있어야 잴 수 있다.
> 등속 이동은 가속도가 0이라 정보가 없으므로, 거리를 늘리는 대신 출발·정지를
> 반복해 **가속 이벤트 수**를 늘렸다.

## 사용한 수식

### 기호 설명 (수식에 쓰인 미지수)

| 기호 | 의미 | 비고 |
|---|---|---|
| `a` | 가속도 벡터 (aₓ, a_y, a_z) | m/s² |
| `v` | 속도 벡터 (vₓ, v_y, v_z) | m/s. odom twist에서 옴 |
| `p` | 위치 벡터 (pₓ, p_y, p_z) | m. odom pose에서 옴 |
| `t` | 시간 | 초 |
| `d/dt` | 시간 미분 (1회) | 속도→가속도 등 |
| `d²/dt²` | 시간 2차 미분 | 위치→가속도 |
| `R_odom` | 로봇 자세 회전행렬 (base_link → world) | odom 쿼터니언에서 계산 |
| `R_LB` | base_link → LiDAR 프레임 회전행렬 | go2_calib.py의 확정값 |
| `R_LBᵀ` | R_LB의 전치 = LiDAR → base_link (역회전) | 회전행렬은 전치가 역행렬 |
| `a_body` | 몸통 IMU가 잰 가속도 (base_link 프레임) | |
| `a_L1` | L1·fix가 잰 가속도 (LiDAR 프레임) | |
| `a_base` | base_link 프레임으로 되돌린 가속도 | 중간 계산값 |
| `a_world` | 월드(world) 프레임의 가속도 | 최종 비교 대상 |
| `v_world` | 월드 프레임의 속도 | R_odom·v_base |
| `r` | 피어슨 상관계수 | −1 ~ +1 |
| `x, y` | 상관 계산의 두 신호 | x=IMU, y=odom 실제가속도 |
| `x̄, ȳ` | 각 신호의 평균 | 평균을 빼서 변동만 비교 |
| `Σ` | 합(시그마) — 모든 샘플에 대해 더함 | |

> **프레임(frame) 3종 정리:**
> - **LiDAR 프레임:** L1 센서 기준 (L1·fix 가속도가 여기 있음)
> - **base_link 프레임:** 로봇 몸통 기준 (body 가속도가 여기 있음)
> - **world 프레임:** 고정된 바깥세상 기준 (여기서 서로 비교)
>
> 세 프레임이 다르므로, 비교하려면 전부 world로 옮겨야 한다. 그 변환에
> `R_odom`, `R_LB`(및 그 역 `R_LBᵀ`)를 쓴다.

### ① 실제 가속도 만들기 — 두 방법 (교차 검증)

오도메트리로부터 "실제 가속도"를 두 가지로 구해 서로 비교한다.
두 방법 결과가 일치하면 계산 방법 자체에 문제가 없다는 뜻이다.

- **A안 (속도 1차 미분):** odom 속도(twist)를 월드 프레임으로 회전 후 1회 미분
  ```
  a = d(v_world)/dt
  ```
  미분을 한 번만 하므로 노이즈가 적다.

- **B안 (위치 2차 미분):** odom 위치를 2회 미분
  ```
  a = d²(p)/dt²
  ```
  전통적 방법이나 노이즈가 크게 증폭된다.

### ② 프레임 정렬 — IMU 가속도를 월드 프레임으로

IMU 가속도(센서 프레임)와 odom 가속도(월드 프레임)를 비교하려면
같은 프레임으로 맞춰야 한다. 소스별로 프레임이 다르다.

- **body:** base_link 프레임 → odom 자세로 월드 변환
  ```
  a_world = R_odom · a_body
  ```
- **L1 / fix:** LiDAR 프레임(= R_LB · base) 이므로, 먼저 base로 되돌린 뒤 월드로.
  ```
  a_base  = R_LBᵀ · a_L1
  a_world = R_odom · a_base
  ```

> **이 프레임 처리가 핵심이었다.** 1차 시도에서는 이 정렬을 근사(모든 소스를
> odom 자세로만 회전)해서, L1·fix가 R_LB만큼 틀어진 것을 반영하지 못했고
> fix 상관이 부호가 뒤집혀 나왔다. R_LBᵀ를 제대로 적용하자 fix가 body와
> 일치했다(아래 결과).

### ③ 상관계수 (피어슨)

각 축에서 IMU 가속도와 실제 가속도의 평균을 뺀 뒤 상관을 구한다.

```
              Σ(x−x̄)(y−ȳ)
r = ─────────────────────────────
     √Σ(x−x̄)² · √Σ(y−ȳ)²
```

- `x` = IMU 가속도(월드), `y` = odom 실제 가속도(월드)
- `r`은 **"패턴 동조"**를 본다. 값의 크기 정확도가 아니다 (그건 실험 3 RMSE).

### 스무딩

미분은 노이즈에 매우 민감하므로, 미분 전후로 이동평균(창 21) 평활화를 적용한다.

## 결과

### 전체 움직임 구간 — 축별 상관 (A안)

| source | x | y | z |
|---|---|---|---|
| L1 | +0.208 | +0.179 | +0.143 |
| body | +0.232 | +0.339 | +0.403 |
| **fix** | **+0.237** | **+0.346** | **+0.404** |

- **fix ≈ body** (소수점 셋째 자리까지 거의 일치) → fix가 body와 동일하게 실제 움직임을 따라감.
- **L1 << body** (특히 y·z에서 확연히 낮음) → L1은 실제 움직임을 못 따라감 = 고장.

### 구간별 (참고)

| 구간 | source | x | y | z |
|---|---|---|---|---|
| 가다서다 | body | +0.219 | +0.375 | +0.358 |
| | fix | +0.228 | +0.385 | +0.351 |
| | L1 | +0.146 | +0.325 | +0.151 |
| 원/곡선 | body | +0.241 | +0.320 | +0.430 |
| | fix | +0.245 | +0.324 | +0.436 |
| | L1 | +0.247 | +0.251 | +0.139 |

→ 모든 구간에서 fix ≈ body, L1은 낮음. 특히 z(회전·수직)에서 L1과 body/fix의 격차가 크다.

### A/B 교차 검증

|a| 상관을 A안·B안 둘 다 계산한 결과, 부호가 뒤집힌 경우 없이 방향·크기가
대체로 일치했다. → **계산 방법 자체에는 문제가 없음** (한 방법의 우연이 아님).

## 결론

1. **fix는 동적(움직임) 상황에서도 정상** — 축별 상관이 body와 소수점까지 일치.
   프레임(R_LB)을 제대로 정렬하자 fix가 body와 동일하게 나왔다.
2. **L1은 여전히 고장** — 실제 움직임과의 상관이 body/fix보다 확연히 낮음(특히 y·z).
   실험 1(정지)에 이어 동적에서도 재확인.
3. **A/B 교차 검증 통과** — 계산 방법에 문제 없음.

### 한계 (정직하게)

- **상관 절대값이 0.4대로 낮다.** 이는 fix 문제가 아니라 **채점 기준(odom)의
  실제 가속도 자체가 노이즈가 심하기 때문**이다. Go2 다리 특성상 가다 서다 시
  속도 프로파일이 덜컹거려, 이를 미분한 "실제 가속도"가 지저분하다.
- 따라서 판단은 절대값이 아니라 **소스 간 상대 비교**로 한다(실험 1과 동일 원칙).
  절대값은 낮아도 fix≈body / L1<<body 패턴은 명확하다.
- odom 정답지의 신뢰도 문제는 **실험 4(오도메트리 신뢰도 분석)**에서 다룬다.

### fix 검증 종합 (실험 1 + 실험 2)

- 실험 1(정적): fix 완벽 (크기 오차 0.25%, 설계값과 0.000° 일치)
- 실험 2(동적): fix ≈ body (상관 소수점까지 일치)
- → **"fix가 부분 수리이고 Point-LIO가 가려준 것"이라는 의심은 아직 근거 없음.**
  fix 자체는 정적·동적 모두 정상. 다른 알고리즘에서의 발산 원인은 fix가 아니라
  다른 곳(입력 방식의 취약성 등)에서 찾아야 한다.

## CSV 파일 보는 법

기록 스크립트는 raw 값만 저장한다. 프레임 정렬·미분·상관은 후처리로 계산한다.

### CSV 구조

```
t, source, ax, ay, az, gx, gy, gz,        # IMU 행 (odom 칸은 비움)
          px, py, pz, qx, qy, qz, qw,     # odom pose (IMU 행은 비움)
          vx, vy, vz, wx, wy, wz          # odom twist (IMU 행은 비움)
```

- IMU 행(L1/body/fix): 앞쪽 가속도·각속도만 채워짐
- odom 행: 뒤쪽 위치·자세·속도만 채워짐

### 1) 구간 확인 (터미널)

```bash
# 소스별 샘플 수
cut -d, -f2 exp2_v2.csv | sort | uniq -c

# odom 만 뽑아 시간대별 위치/속도 훑기 (파이썬에서 source=='odom' 필터)
```

### 2) 상관 계산 (실제 사용한 분석)

`analyze_exp2_v2.py`로 저장하고 `PATH`만 바꿔 실행하면 결과가 재현된다.
핵심 로직은 위 "사용한 수식"과 동일하다.

```python
import csv, math, numpy as np
from collections import defaultdict

PATH='exp2_v2.csv'
R_LB=np.array([[+0.523029,-0.838576,+0.152420],
               [-0.810712,-0.544668,-0.214668],
               [+0.263034,-0.011292,-0.964721]])

# 1) CSV 읽기: imu[source]=[(t,ax,ay,az)...], odom=[(t,pos,quat,vel)...]
# 2) quat -> 회전행렬 R_odom  (body->world)
# 3) 실제 가속도:
#    A = d(R_odom·v_base)/dt      (속도 1차미분)
#    B = d²(pos)/dt²              (위치 2차미분)
# 4) IMU 가속도를 월드로:
#    body: R_odom · a_body
#    L1/fix: R_odom · (R_LBᵀ · a)   <- LiDAR프레임 되돌리기
# 5) 리샘플(odom 시간격자) 후, 축별 np.corrcoef
```

> 전체 코드는 `analyze_exp2_v2.py` 참조. 미분 전후 이동평균(창 21) 스무딩 포함.

### 3) 판정 기준

| 무엇을 보나 | 판정 |
|---|---|
| fix 정상 여부 | fix 상관 ≈ body 상관 이면 정상 |
| L1 고장 정도 | L1 상관 << body 상관 이면 고장 |
| 계산 방법 검증 | A안·B안 결과가 일치하면 방법에 문제 없음 |

> **주의:** 상관 절대값(0.4대)이 낮다고 "fix가 나쁘다"로 읽지 말 것.
> 낮은 절대값은 odom 기준의 노이즈 탓이며, 판단은 **소스 간 상대 비교**로 한다.
