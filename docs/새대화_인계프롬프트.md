```
Go2 X 4족 로봇의 LiDAR-Inertial Odometry 프로젝트를 이어서 진행합니다.
한경국립대 ICT로봇공학과 학부연구생이고, 2월 순천 대회에서 실외 GPS 웨이포인트
자율주행이 목표입니다. 주행 제어는 팀원이 담당하고, 저는 LIO 파이프라인과
위치 추정 인터페이스까지를 맡습니다.
한국어로, 개념 먼저 설명하고 단계별로 확인받으며 진행하는 방식을 선호합니다.

### 해결한 것 1 — /utlidar/imu 가속도계 불량

Point-LIO가 회전 구간에서 발산하는 문제의 원인을 찾아 해결했습니다.

원인: /utlidar/imu 의 가속도계 데이터가 사용 불가 상태였습니다.
- 실제 로봇 가속도와의 상관이 어떤 좌표 변환을 넣어도 0.19 이하
  (본체 IMU /lowstate 는 0.83)
- 중력 방향이 실제와 149도 오정렬
- 자이로는 정상이며 LiDAR 클라우드 좌표계와 1.87도 이내로 평행
- 따라서 extrinsic_R: identity 는 원래 옳았고, 문제는 가속도계 하나

해결: l1_imu_fix.py 브리지 노드로 자이로는 /utlidar/imu 그대로,
가속도계는 /lowstate 본체 것을 LiDAR 프레임으로 회전시켜 /l1_imu_fixed 발행.
발산이 완전히 사라졌습니다.

### 해결한 것 2 — 실험 규약 (이게 두 번째로 중요합니다)

같은 bag, 같은 설정인데 결과가 재현되지 않는 문제가 있었습니다. 원인 두 가지:

(1) CYCLONEDDS_URI 가 설정된 상태로 로컬 재생하면 메시지가 유실됩니다.
    setup_go2.sh 가 USB-이더넷 인터페이스 하나로 DDS를 묶기 때문입니다.
    오프라인 실험에서는 반드시 unset 해야 합니다.
(2) 실시간 재생에서는 Point-LIO가 못 따라갑니다. -r 0.5 필수입니다.

이 둘을 적용하니 z RMSE 가 30 -> 17.0 ± 0.3 mm (변동 2%) 로 개선되고
재현성이 확보됐습니다.

그래서 실험 규약을 이렇게 확정했습니다:
- 환경: srcoff = source 2줄 + unset CYCLONEDDS_URI
- 재생: -r 0.5
- 반복: 설정당 최소 3회, 평균±표준편차로 판정
- 주 지표: z RMSE (변동 2%)
- 참고 지표: 루프 클로저 (변동 42%, 20% 미만 차이는 판정 불가)

루프 클로저 변동이 큰 이유는 환경 관측성 부족입니다. 이 데이터는 최대 사거리
2.4~5.6 m 에 대부분 지면인데, 평면 지면은 요(yaw)를 전혀 제약하지 못합니다.
벽이 시야에서 사라지는 구간에서 요가 표류하고 33 m 를 걸으며 증폭됩니다.
알고리즘 결함이 아니라 정상적인 SLAM 거동이며, 실외에서는 GPS 융합이
필요한 근거가 됩니다.

### 확정된 외부 파라미터 (go2_calib.py)

R_LB (base_link -> L1/LiDAR 회전), yaw 성분 -127.9도 ±0.5도:
  [+0.523029, -0.838576, +0.152420,
   -0.810712, -0.544668, -0.214668,
   +0.263034, -0.011292, -0.964721]

LEVER (base_link 원점 -> LiDAR 원점, base_link 프레임) = (0.322, 0.005, 0.050) m
  x,y 는 최소자승 추정(잔차 40% 개선), z 는 관측 불가로 추정값

### 현재 성능 (Point-LIO, srcoff + -r 0.5, 3회)

z RMSE       17.0 ± 0.3 mm
z 최대오차    50.4 ± 1.6 mm
최종 z 오차   -31.3 ± 4.7 mm   (참값 -2.0)
루프 클로저   0.785 ± 0.327 m  (참값 0.556, 개별 0.567/0.626/1.161)
총거리       48.46 ± 0.63 m   (참값 32.53)

### 폐기된 가설 (다시 꺼내지 말 것)

- acc_norm 을 10.41 로 고치기: 6.4% 스케일 오차는 실측 사실이나 원인 아님
- "자이로 부호가 반대": 지면 법선 부호 오판에서 나온 오류. 자이로는 정상
- 벽 거리 회귀 yaw -2.5도 / 지도 선명도 yaw +60/+130도: 판별력 부족
- depth=200 이 결과 악화 원인: depth 10/200 범위 완전히 겹침
- 출력 레이트가 총거리 44% 과대의 원인: 8.5kHz -> 15Hz 로 바꿔도 동일
```

## 인계 시 주의

- **`go2_calib.py` 값이 바뀌면** 세 노드(`l1_imu_fix`, `robot_pose`, `goto_node`)에
  모두 반영해야 한다. 새 대화에서 값을 고칠 일이 생기면 반드시 짚어줄 것을 요청
- **`camera_init` 원점은 LIO 노드 실행 시점의 로봇 위치.** 재시작하면 웨이포인트 무효
- **깨진 IMU 로 한 기존 알고리즘 비교**는 실패 방식(fail-loud vs fail-silent)만
  유효하고 오차 크기 비교는 무효. 진단정리 §7
- **`/robot_pose` 이름 변경 필요.** 로봇의 `/utlidar/robot_pose` 와 헷갈린다.
  `/lio/base_pose` 로 바꿀 것. 팀원 인계 전에
- **미확인 토픽 3개**: `/utlidar/cloud_base`(base 프레임 점군일 가능성),
  `/uslam/*`(Unitree 자체 SLAM), `/lio_sam_ros2/mapping/odometry`
- `LEVER` z 성분은 추정값. 실측하면 갱신
- `run_exp.sh` 는 미검증. 수동 절차가 확실하다
