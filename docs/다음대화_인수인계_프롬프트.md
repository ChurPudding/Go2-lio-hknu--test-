# FAST-LIO Go2 적용 — 이어서 작업 (회전 시 정합 붕괴 해결)

## 지금 상황 한 줄 요약
FAST-LIO가 Go2 L1에서 **정지 상태는 완벽히 매핑되나, 로봇이 회전/이동하면
`No Effective Points`가 나며 궤적이 폭주**한다. 원인은 **LiDAR-IMU extrinsic
(특히 회전 성분)이 실제 하드웨어와 안 맞기 때문**으로 규명 완료. 남은 과제는
**실제 extrinsic을 정밀 측정**하는 것.

## 목표
움직일 때도 정합이 유지되어, 이동하며 지도가 확장되게 만든다.
최종적으로 rosbag 녹화 → FAST-LIO / FAST-LIO2 / Point-LIO 성능 비교(교수님 과제).

## 환경 (자동 소싱됨, setup_go2.sh 실행 불필요)
- Galaxy Book / Ubuntu 22.04 / ROS2 Humble / CycloneDDS
- 로봇 192.168.123.161, DOMAIN_ID=0
- FAST-LIO: ~/fastlio_ws (Ericsii/FAST_LIO, 실제로는 FAST-LIO2 기반)
- config 넣는 곳: ~/fastlio_ws/install/fast_lio/share/fast_lio/config/
  (src/ 아니라 install/ 에 직접 cp 해야 함. 안 그러면 lidar_type 1로 죽음 exit -11)
- 실행 후 반드시 로그에서 `lidar_type 2` 확인

## 라이다 살리는 법 (중요, 매번 필요)
Go2는 유휴 시 라이다를 끈다. sport 토픽에 구독자가 붙어야 깨어난다.
→ 터미널 1에서 `ros2 topic echo /sportmodestate` 를 항상 켜둔 채 작업.
(배터리 문제 아님. 35%에서도 sport 구독하면 라이다 돈다.)

## 오늘 해결한 것 (다시 건드리지 말 것)
1. **timestamp_unit = 0** (초 단위 float32, 점당 ~7.73us). 실측 확정. (2로 하면 움직일 때 깨짐)
2. **좁은 실내 튜닝**: blind 0.2, filter_size_surf/map 0.1
3. **사족보행 노이즈**: gyr_cov 0.5, acc_cov 0.5
4. **QoS**: 몸통 IMU 브리지는 RELIABLE 이어야 FAST-LIO가 받음
5. **IMU가 두 개**:
   - `/utlidar/imu` = L1 라이다 **내장** IMU (frame_id=utlidar_imu). 기울어 있음.
     정지 시 accel x=3.4, z=9.9 → 피치 약 19도.
   - `/lowstate` 안 몸통 IMU = **수평** (accel x≈0, z=9.5). 독립 토픽 아니라 브리지 필요.

## 핵심 미해결: extrinsic 회전
- URDF radar_joint: xyz=[0.28945,0,-0.046825], rpy=[0,2.8782,0]=164.9도(=아래에서 15.1도)
- URDF imu_joint(몸통): xyz=[-0.02557,0,0.04232], rpy=[0,0,0] (수평)
- **URDF(15.1도)와 실측(19도)이 4도 다름** → URDF가 실물과 안 맞음
- **결정적 단서**: 로봇이 `/utlidar/lidar_state` 의 `imu_rpy`로 라이다 내장 IMU
  실제 자세를 알려줌 → **roll 110.85, pitch 18.40, yaw -0.196 (deg)**.
  지금까지 피치만 맞추고 **roll 110도를 못 넣은 게 회전 폭주의 원인**으로 추정.
  (단, 이 rpy를 단순 RzRyRx로 조립하면 중력 검증 실패 → 로봇의 회전 순서/정의가
   다름. 수동 계산으로는 못 맞춤.)

## 시도했으나 실패한 접근 (반복하지 말 것)
- 몸통 IMU + URDF extrinsic(164.9도): 정지OK, 회전 시 궤적 일직선 폭주 (T 오차 31cm 증폭)
- 몸통 IMU + 실측 19도 extrinsic: 지도 수평 성공했으나 회전 시 여전히 폭주
- 라이다 내장 IMU + 단위행렬 + 온라인추정: 정지OK, 움직이면 No Effective Points
- extrinsic_est_en=true 온라인 추정: 제자리 회전만으론 수렴 못 함(직진 필요)
→ 수동 extrinsic 조정과 온라인 추정 모두 한계. **정밀 측정 도구가 답.**

## ★ 다음에 할 일 (우선순위 순)

### 1순위: LiDAR_IMU_Init 캘리브레이션 (근본 해결책)
- hku-mars/LiDAR_IMU_Init (FAST-LIO 제작팀 작품, ROS2 포팅본 확인 필요)
- 로봇/센서를 여러 방향으로 흔들면 LiDAR-IMU extrinsic(회전+위치) 자동 정밀 측정
- 오늘 손으로 못 잡은 roll 110도 성분을 정확히 구해줄 것
- 출력된 extrinsic_R, extrinsic_T를 config에 넣으면 회전 문제 해결 기대
- 작업: ROS2 Humble 빌드 → /utlidar/cloud + /utlidar/imu 로 캘리브레이션 실행

### 2순위(대안): 로봇 자체 오도메트리를 ground truth로 활용
- `/utlidar/robot_odom` = 로봇 내장 uSLAM 오도메트리. **extrinsic이 이미 완벽**.
  (제자리 회전 시 position이 소수점 4자리만 흔들림 = 정확)
- FAST-LIO를 못 고쳐도, 이걸 정답 기준으로 삼아 "FAST-LIO 대비 오차" 보고 가능
- 교수님 과제(성능 비교)에는 이게 오히려 좋은 비교 baseline

### 3순위: rosbag 녹화 후 오프라인 반복 실험
- 일단 되는 구간이라도 `ros2 bag record /utlidar/cloud /utlidar/imu /sportmodestate`
- 로봇 없이 config 튜닝 반복 가능 → LiDAR_IMU_Init도 bag으로 돌릴 수 있음

## 만든 파일들 (~/ 및 output에 있음)
- go2_l1_body_measured.yaml: 몸통IMU+실측19도. 지도 수평까지는 성공한 버전
- go2_l1_lidarimu.yaml: 라이다내장IMU+단위행렬+온라인추정
- body_imu_bridge.py: /lowstate→/body_imu 변환 (RELIABLE QoS). 몸통IMU 쓸 때만 필요
- cloud_to_csv.py: 포인트클라우드 CSV 저장 + voxel 다운샘플
- check_imu.py: IMU 정체(몸통/내장) 판별
