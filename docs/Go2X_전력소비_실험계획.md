# Go2 X 전력 소비 측정 실험 계획

## 1. 목적

Unitree Go2 X의 전력 소비를 **동작 종류**와 **하중(payload)**에 따라 정량적으로 측정한다.
최종 목표는 두 가지다.

1. 각 동작·하중 조건에서의 소비 전력을 확보한다.
2. 이를 바탕으로 **경로 기반 배터리 예측 모델**을 세워, 대회 주행 시 예상 주행거리·주행시간을 계산한다.

---

## 2. 배경 원리

전력 소비는 물리 현상이므로, 실제 흐르는 전류를 측정해야 한다. 핵심 인과 사슬은 다음과 같다.

> 실제 질량 ↑ → 관절 유지·구동 토크 ↑ → 전류 ↑ → I²R(동손) ↑ → 배터리 전력 ↑

주의할 개념 두 가지:

- **정지 상태에서도 전력이 소비된다.** 다리가 움직이지 않아 기계적 출력(τ·ω)은 0이지만, 자세를 유지하는 토크 때문에 I²R 손실이 계속 발생한다.
- **손실은 토크의 제곱에 가깝게 증가한다.** 토크는 하중에 비례하므로, 이상적으로 전력 증가분은 하중의 제곱에 가깝다. 다만 실사용 하중 범위(수 kg)에서는 baseline이 크기 때문에 좁은 구간에서는 거의 선형처럼 보일 수 있다.

---

## 3. 측정 방법

두 방법을 병행한다. 서로를 검증하는 관계다. 두 방법 모두 **`/lowstate` 토픽 하나의 구독만으로** 구현된다(BMS·전원·모터·발 접지력·온도가 모두 이 토픽에 들어 있음).

### 방법 A — BMS 총량 (top-down)

- 배터리 전체 전압 × 전류로 **총 소비 전력**을 측정한다.
- 데이터 출처: `/lowstate`의 `bms_state`, `power_v`.
- **총 전력 공식**: `P_total = power_v × (|bms_state.current| / 1000)`
  - `bms_state.current`는 mA 단위로 추정되며 방전 시 음수 부호로 나온다. 절댓값을 취한다.
  - `power_v`는 전체 전압(약 32V). `cell_vol` 8개 셀 합(/1000)으로 교차검증한다.
- **주의**: `power_a` 필드가 별도로 존재하지만 값이 물리적으로 낮게 나온다(정지 시 약 8.8W). 이는 다른 레일이거나 스케일이 다른 값으로 의심되므로 **총 전력 산정에는 쓰지 않는다.** BMS 기준값(정지 시 약 59W)이 물리적으로 타당하다.
- **에너지 교차검증**: `soc`(배터리 잔량 %) 변화량으로 누적 에너지를 한 번 더 검증한다.
- 여기서 이미 알고 있는 센서 소비(예: LiDAR L1 약 6W 등 상수)를 빼면 나머지를 "모터 전체"로 귀속시킬 수 있다.
- 장점: 실측 기반이라 정확하고 구현이 간단하다.
- 한계: 모터를 하나의 덩어리로만 본다. 개별 모터 구분은 안 된다.
- 산출: **하중 → 총 전력** 커브, 주행시간 예측.

### 방법 B — 모터별 추정 (bottom-up)

- 데이터 출처: `/lowstate`의 `motor_state` 배열.
- **중요**: `motor_state`에는 **전류(current) 필드가 없다.** 관절별 추정 토크 `tau_est`와 각속도 `dq`만 제공된다. 따라서 방법 B는 "전류 직접 측정"이 아니라 **토크 기반 추정**이다.
- **활성 모터**: 배열 앞쪽 12개만 활성(`mode == 1`)이고 뒤쪽은 0이다. `mode == 1`로 필터하거나 앞 12개만 합산한다.
- 추정은 두 갈래로 나눈다:
  - **기계적 출력만**: `P_mech = tau_est × dq`
    → "어느 관절이 실제로 일을 하는가"(움직임 분포)에는 좋지만, 전기 소비를 크게 과소평가한다. **정지 시 dq ≈ 0이라 0W가 나와, 자세 유지 전력(baseline 대부분)을 통째로 놓친다.**
  - **전기 소비 추정**: `P_joint ≈ tau_est × dq + (tau_est / Kt)² × R`
    → 두 번째 항(동손, 토크²)이 저속·정지에서 지배적이다. `Kt`(토크 상수)와 `R`(상 저항)은 Go2 모터 스펙에서 확보해야 한다.
- 장점: 세밀하다. 어느 다리·관절에 부하가 몰리는지 분석 가능.
- 한계: `Kt`·`R` 가정이 들어가 오차가 있을 수 있다. 정지 시 부하 분포 분석에는 동손 항(토크²) 하나만으로도 충분히 유의미하다.
- 산출: **하중·동작이 어디에 실리는가**(관절별 분포), 마운트 위치·발열 진단.

### 두 방법의 관계

방법 A(총량)를 먼저 확보해 기준선을 잡고, 방법 B(모터별)로 분포를 채운다.
검증 조건: **(모터별 합 + 센서 상수) ≈ BMS 총 전력**. 이 등식이 맞는지로 방법 B의 신뢰도를 판단한다.

## 4. 실험 변수

| 구분 | 변수 |
|------|------|
| 독립 변수 | 동작 조건, 하중(kg) |
| 종속 변수 | 평균 전력(W), 에너지(Wh), 정규화 지표(Wh/m, Wh/rad, Wh/분) |
| 통제 변수 | 보행 모드(gait), 명령 속도, 지면, 모터 온도, 배터리 전압 |

전압은 방전에 따라 떨어지므로 전류가 아닌 **실측 전력(V×I)**을 기록한다.

## 5. 측정 조건

각 조건은 앞 조건에 성분을 하나씩 더하는 계층 구조다.

| 단계 | 조건 | 명령 | 분리해내는 것 | 주요 지표 |
|------|------|------|----------------|-----------|
| 1a | 정지 — 스탠드 락 | `StandUp` (위치 제어) | 고강성 유지 baseline | W |
| 1b | 정지 — 균형 서기 | `BalanceStand` (균형 제어) | 저강성 유지 baseline | W |
| 2 | 저속 보행(제자리 대체) | `Move(0.1, 0, 0)` | 보행 사이클 비용 | W, Wh/분 |
| 3 | 직선 주행 | `Move(vx, 0, 0)` | 순수 직진 이동 비용 | **Wh/m** |
| 4 | 제자리 회전 | `Move(0, 0, vyaw)` | 순수 방향 전환 비용 | **Wh/rad** |
| 5 | 곡선 주행 | `Move(vx, 0, vyaw)` | 합성 검증 + coupling 측정 | Wh/m, Wh/rad |

### 정지 두 모드를 나누는 이유

정지 상태는 물리적으로 다른 두 개의 baseline을 가진다. 손으로 밀었을 때의 반응 차이가 곧 전력 차이의 원인이다.

- **스탠드 락(`StandUp`, 위치 제어)**: 각 관절이 목표 각도를 지키려 강한 복원 토크를 상시 유지한다. 밀어도 안 움직인다(고강성). 토크가 크니 I²R 손실도 크다.
- **균형 서기(`BalanceStand`, 균형 제어)**: 넘어지지 않을 최소 토크만 쓴다. 밀면 부드럽게 밀린다(저강성). 손실이 작다.

원리상 스탠드 락이 더 큰 baseline을 가질 가능성이 높다. 이 차이는 대회에서 **웨이포인트 도착 후 대기 중 어느 모드로 서 있을지**를 결정하는 에너지 절약 운용 전략의 근거가 된다.

> Go2 sport API에는 "제자리 발 구르기" 전용 명령이 없다(이동은 `Move(vx, vy, vyaw)` 하나뿐). 그래서 조건 2는 저속 보행 `Move(0.1, 0, 0)`으로 정의한다.

### 성분 분해 논리

- (조건2 − 조건1b) ≈ 보행 동작 자체의 비용 (전진 일 없이 다리만 흔드는 값). 보행은 균형 제어 기반이므로 baseline은 균형 서기(1b)와 비교한다.
- (조건3 − 조건2) ≈ 실제 이동(추진) 비용
- 조건4는 각도 기준으로 정규화한다. 제자리 회전은 몸이 전진하지 않으므로 거리(m)가 아닌 **각도(rad)** 로 나눈다.
- 조건5는 직진·회전이 동시에 들어간 파생 동작이다. 단독으로는 원인 분리가 안 되므로, 조건3·4를 먼저 확보한 뒤 마지막에 측정한다.

### Coupling(연성) 항

곡선 주행은 직진과 회전의 단순 합이 아닐 수 있다(안·바깥 다리 속도 차에 의한 slip, 원심력에 의한 무게중심 이동 등). 다음을 계산해 상호작용 크기를 본다.

> coupling = 실측 곡선 전력 − (직진 성분 + 회전 성분)

- 0에 가까움 → 직진·회전만으로 곡선을 예측 가능
- 0에서 멀음 → 곡선은 별도 데이터가 필요

곡선은 회전 반경에 따라 달라지므로, **여러 반경(예: 큰 원·작은 원)** 으로 나눠 측정한다.

## 6. 하중(payload) 설계

- **실제 무게를 물리적으로 싣는다.** (실물 로봇 측정 기준)
- 정확히 아는 무게를 사용한다: 아령 원판, 물병(1L=1kg), 계량한 모래주머니 등.
- **실장비가 올라갈 위치(LiDAR·컴퓨트 자리)에 배치**한다. 같은 무게라도 배치 위치에 따라 무게중심과 관절별 부하가 달라진다.
- 주행 중 흔들리지 않게 **단단히 고정**한다.
- 하중 수준: 0, 1, 2, 3 … kg (실장비 예상 무게를 반드시 포함)

## 7. 로깅 스키마

한 줄 = 한 샘플.

```
timestamp,
condition,        # stand_lock / stand_balance / march / straight / spin / curve
payload_kg,
gait_mode,
cmd_speed,        # 직진 명령 속도 (vx)
cmd_yaw_rate,     # 회전 명령 각속도 (ω)
voltage,          # /lowstate power_v
current,          # /lowstate bms_state.current 절댓값 (mA→A)
power_W,          # voltage × current
soc,              # /lowstate bms_state.soc (에너지 교차검증용)
distance_m,       # 직선·곡선
angle_rad,        # 회전·곡선
motor_temp_max,   # /lowstate motor_state[*].temperature 최댓값
foot_force,       # /lowstate foot_force (보행 위상 판별)
trial_id
```

방법 B(모터별)를 함께 기록할 경우, `motor_state` 12개 각각의 `tau_est`·`dq`·`temperature`를 별도 로그로 남긴다.

시행 종료 후 파생값 계산: `duration_s`, `energy_Wh`, `avg_W`, 그리고 조건에 따라 `Wh/m` / `Wh/rad`.

## 8. 실험 프로토콜

- **각 조건·하중당 3회 이상 반복** → 평균과 표준편차를 산출한다. 시행마다 값이 흔들리므로 반복이 필수다.
- **과도구간 제거**: 상태 전환 직후 3~5초는 버리고, 안정된 구간만 평균 낸다.
- **온도·전압 드리프트 통제**:
  - 하중을 순서대로만 쭉 재면 뒤로 갈수록 모터 발열·배터리 방전이 누적되어 "하중 효과"에 "시간 효과"가 섞인다.
  - 대책: 시행 사이 충분히 쉬고, `motor_temp_max`와 `voltage`를 반드시 로깅해 사후에 교란 여부를 확인한다.
- **거리 측정**: 바닥에 직선 코스(예: 5m)를 테이프로 표시하고, 그 구간을 통과하는 동안의 에너지만 잘라 쓴다.
- **회전 측정**: 제자리에서 360°를 N회 회전시키고 총 에너지를 각도로 나눠 Wh/rad를 구한다.
- **안전**: 하중이 실리면 무게중심이 바뀌어 넘어질 수 있으므로, 직선 경로 확보 및 감시 하에 진행한다.

## 9. 경로 기반 배터리 예측 모델

조건별 정규화 지표가 확보되면, 임의 경로의 총 에너지를 다음과 같이 합산한다.

> 총 에너지 ≈ (직진 거리 × Wh/m) + (총 회전각 × Wh/rad) + (정지 대기시간 × baseline W) + (곡선 구간 보정)

여기서 예상 주행거리·시간을 계산한다.

> 예상 주행거리 = (사용 가능 배터리 Wh) ÷ (Wh/m)

- 배터리 총량: 약 236.8 Wh
- 0까지 방전하지 않으므로 사용 가능치는 약 80%인 **약 190 Wh**로 잡는다.
