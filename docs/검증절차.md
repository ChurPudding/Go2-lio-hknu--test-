# 검증 절차 — Go2 LIO 센서·결과 진단

이번 진단에서 실제로 돌린 검증들을 재현 가능한 형태로 정리한다. 새 bag(실외, 다른 로봇, 다른 알고리즘 결과)에 그대로 적용할 수 있다.

**필요한 것:** `go2lib.py`, Python 3 + numpy + scipy. **ROS2는 필요 없다** — `.db3`는 SQLite이므로 sqlite3 + 수동 CDR 역직렬화로 읽는다.

## 검증 1 — 정지 구간 중력·바이어스·포화

가장 기본이고, 이번 진단의 출발점이었다.

```python
segs = still_segments(t, g, a)          # |gyro|<0.08 rad/s 인 0.5s 윈도우
A = np.vstack([a[s:e] for s, e in segs])

print("정지 %d구간 %d샘플" % (len(segs), len(A)))

print("up 단위벡터", np.round(u, 4), " 자기 +z 에서 %.1f deg"
      % np.degrees(np.arccos(np.clip(u[2], -1, 1))))
print("자이로 바이어스 %s rad/s = %s deg/s"
      % (np.round(G.mean(0), 6), np.round(np.degrees(G.mean(0)), 4)))
```

## 검증 2 — 기준선(`robot_odom`) 신뢰성

정량 평가를 하려면 참값이 먼저 필요하다.

```python
ot, op, oq = B.odom(); ot -= T0
print("z: 범위 %.3f~%.3f, std %.1fmm, p-p %.1fmm, 시작-끝 %.1fmm"
      % (op[:,2].min(), op[:,2].max(), 1e3*op[:,2].std(),
         1e3*(op[:,2].max()-op[:,2].min()), 1e3*(op[-1,2]-op[0,2])))
R = q2R(oq)
roll  = np.degrees(np.arctan2(R[:,2,1], R[:,2,2]))
pitch = np.degrees(-np.arcsin(np.clip(R[:,2,0], -1, 1)))
print("roll/pitch 평균 %+.2f / %+.2f deg  (0 근처면 중력정렬 프레임)"
      % (roll.mean(), pitch.mean()))
d = np.linalg.norm(np.diff(op[:,:2], axis=0), axis=1)
print("총 경로 %.2f m, 루프클로저 %.3f m (%.1f%%)"
      % (d.sum(), np.linalg.norm(op[-1,:2]-op[0,:2]),
         100*np.linalg.norm(op[-1,:2]-op[0,:2])/d.sum()))
```

**결과**

```
z: 범위 0.290~0.322, std 5.1mm, p-p 31.8mm, 시작-끝 1.8mm
roll/pitch 평균 -0.76 / +0.44 deg
총 경로 32.85 m, 루프클로저 0.560 m (1.7%)
```

**왜 z만 믿을 수 있는가:** x·y·yaw는 다리 운동학의 *적분*이라 시간에 비례해 드리프트하지만, **z는 적분이 아니다.** 발이 지면에 닿아 있을 때 관절각으로 몸통 높이를 직접 계산하므로 매 스텝마다 지면이 z를 재고정한다.

**따라서**

- z 처짐 판정 → `robot_odom` z를 정답으로 사용 (허용 ±20 mm)
- 수평 정확도 판정 → x·y를 쓰지 말고 **루프 클로저**로

## 검증 3 — 회전 구간 추출

LIO는 회전에서 깨지므로 구간을 특정해 두면 이후 분석이 쉬워진다.

```python
u = np.array([0.3418, -0.0004, 0.9398])       # 검증 1의 up
wz = np.convolve(g @ u, np.ones(51)/51, mode='same')   # 연직축 각속도
rot = np.abs(wz) > 0.35
idx = np.where(rot)[0]; segs = []
if len(idx):
    s = p = idx[0]
    for i in idx[1:]:
        if i - p > 75: segs.append((s, p)); s = i
        p = i
    segs.append((s, p))
segs = [x for x in segs if t[x[1]] - t[x[0]] > 0.8]
oy = np.degrees(yaw_of(oq))
for k, (s, e) in enumerate(segs):
    y0, y1 = np.interp([t[s], t[e]], ot, oy)
    print("R%-2d t=%6.2f~%6.2f s  yaw %+7.1f deg" % (k, t[s], t[e], y1-y0))
```

**결과:** 16개 구간, 누적 회전 2281°(6.3바퀴), 최대 165°/s. 주요 구간 R2(15.7~18.5 s), R3(27.7~30.5 s), R6(38.2~40.7 s), R8(46.5~49.3 s), R9(51.3~53.7 s), R14(85.5~89.2 s).

> **주의:** L1 IMU는 기울어져 있으므로 자이로 z를 그대로 쓰면 안 된다. 반드시 실측 중력축에 투영한다.

## 검증 4 — 가속도계 유효성 (결정적)

**이번 진단에서 원인을 확정한 검증이다.** 정지 상태의 중력 벡터가 그럴듯해 보여도, 실제 운동을 따라가지 못하면 그 IMU는 쓸 수 없다.

원리: IMU 가속도를 월드 프레임으로 회전시킨 뒤 `robot_odom` 위치의 2차 미분과 상관을 낸다. 같은 물체의 가속도이므로 상관이 높아야 정상이다.

```python
from scipy.ndimage import uniform_filter1d
ot, op, oq = B.odom(); ot -= T0
qi = np.stack([np.interp(t, ot, oq[:,k]) for k in range(4)], 1)
Rw = q2R(qi)                                   # base -> world
P  = np.stack([np.interp(t, ot, op[:,k]) for k in range(3)], 1)
dt = np.median(np.diff(t))
V  = np.gradient(uniform_filter1d(P, 101, axis=0), dt, axis=0)
Ao = uniform_filter1d(np.gradient(uniform_filter1d(V,101,axis=0), dt, axis=0), 101, axis=0)

lt, lq, lg, la = B.lowstate(); lt -= T0
Ab = np.stack([np.interp(t-0.008, lt, la[:,k]) for k in range(3)], 1)

def score(name, acc_body):
    aw = np.einsum('nij,nj->ni', Rw, acc_body)
    Aw = uniform_filter1d(aw, 101, axis=0); Aw -= Aw.mean(0)
    Ac = Ao - Ao.mean(0)
    c = [np.corrcoef(Aw[:,k], Ac[:,k])[0,1] for k in range(3)]
    print("%-34s ax %+.3f  ay %+.3f  az평균 %+.3f" % (name, c[0], c[1], aw[:,2].mean()))

nL = np.array([0.1544,-0.1779,-0.9719])        # 검증 5의 LiDAR up
ub = np.array([-0.0091,-0.0256,0.9996])        # 본체 up
score("L1 accel = LiDAR 프레임 가정", (rot_align(nL,ub) @ a.T).T)
score("L1 accel = 자기 up 기준 가정", (rot_align(np.array([0.3418,-0.0004,0.9398]),ub) @ a.T).T)
score("본체 IMU (/lowstate)",          Ab)
```

**결과**

| 가정 | ax 상관 | ay 상관 | az 평균 |
|---|---|---|---|
| L1 accel = LiDAR 프레임 | −0.187 | −0.130 | −8.967 |
| L1 accel = 자기 up 기준 | −0.036 | +0.168 | +10.394 |
| **본체 IMU** | **+0.833** | **+0.787** | **+9.455** |

**판정 기준:** 상관이 **0.6 이상**이면 정상, **0.3 이하면 그 IMU의 가속도계는 사용 불가**다. 어떤 좌표 변환을 넣어도 올라가지 않는다면 회전 문제가 아니라 데이터 자체의 문제다.

`az 평균`도 함께 본다. 정지에서 시작해 정지로 끝나면 참가속도의 시간평균은 0이므로, 월드 프레임 평균은 순수 중력 `(0, 0, +9.807)`이어야 한다.

## 검증 5 — 좌표계 정합 (LiDAR ↔ IMU)

`extrinsic_R`이 맞는지 확인한다. 지면 평면의 법선이 중력 방향이라는 사실을 이용한다.

```python
rng = np.random.default_rng(0)
C = B.clouds()
P = np.vstack([C[i][1] for i in range(10, 95)])     # 정지 구간 누적
n, d, inl, Pf = ransac_plane(P, rng)
# 부호 결정: 지면은 센서 아래에 있다. 클라우드 z 분포로 확인할 것
if n[2] > 0 and np.median(P[:,2]) > 0:
    n, d = -n, -d
print("지면 up(LiDAR) %s, inlier %d/%d (%.0f%%), 센서높이 %.3f m"
      % (np.round(n,4), len(inl), len(Pf), 100*len(inl)/len(Pf), abs(d)))
print("확산 x[%.1f,%.1f] y[%.1f,%.1f]"
      % (inl[:,0].min(), inl[:,0].max(), inl[:,1].min(), inl[:,1].max()))
uA = np.array([0.3418,-0.0004,0.9398])
print("가속도계 up 과의 각도 %.2f deg" % np.degrees(np.arccos(np.clip(n@uA,-1,1))))
```

**결과**

```
지면 up(LiDAR) [ 0.1508 -0.1809 -0.9719], inlier 52098/138522 (38%), 센서높이 0.358 m
확산 x[-1.1,+2.4] y[-4.0,+2.4]
가속도계 up 과의 각도 149.4 deg
```

### 함정 — 법선의 부호

**RANSAC은 평면의 방향만 주고 부호는 주지 않는다.** 이번에 부호를 반대로 잡아 한동안 자이로를 범인으로 오판했다.

부호는 **클라우드의 좌표 분포로** 결정한다.

```python
print("클라우드 z 분포 (1/50/99%%):", np.round(np.percentile(P[:,2],[1,50,99]),3))
```

`[0.06, 0.43, 0.65]` — 전부 양수다. 지면 점이 +z 쪽에 있다는 뜻이므로 **L1의 +z축은 아래를 향하고**, up은 −z 쪽이다.

**신뢰성 확인:** inlier가 30% 이상이고, 확산이 수 m에 걸치며, 두 번째로 큰 평면이 지면과 약 90°(벽)면 피팅을 믿어도 된다.

**판정:** 지면 법선과 IMU up의 각도가 `extrinsic_R`이 설명하는 회전과 일치해야 한다. 단위행렬을 쓰는데 각도가 5°를 넘으면 extrinsic이 틀렸거나 IMU가 이상한 것이다.

## 검증 6 — 외부 파라미터 추정 (자이로 상관)

두 IMU가 같은 강체에 붙어 있으면, 각속도 벡터쌍을 Kabsch 정렬해 **회전 3자유도를 전부** 결정할 수 있다.

> 평균이 아니라 **상관**이 정보를 준다. 두 자이로를 평균내면 잡음만 줄 뿐 각도 정보는 생기지 않는다.

```python
from scipy.signal import butter, filtfilt
lt, lq, lg, la = B.lowstate(); lt -= T0
FS = 100.0; grid = np.arange(1.0, t[-1]-1.0, 1/FS)

def prep(tt, X, fc, lag=0.0):
    Y = np.stack([np.interp(grid+lag, tt, X[:,k]) for k in range(3)], 1)
    b, aa = butter(4, fc/(FS/2), 'low')
    return filtfilt(b, aa, Y, axis=0)

for fc in [2, 5, 10, 20, 40]:
    A0 = prep(t, g, fc); best = (0, None, None)
    for lag in np.arange(-0.03, 0.03, 0.001):
        Bq = prep(lt, lg, fc, lag)
        s = np.linalg.norm(A0, axis=1) > 0.4
        R, qq = kabsch(A0[s], Bq[s])
        if qq > best[0]: best = (qq, lag, R)
    qq, lag, R = best
    print("대역 %2dHz  lag %+5.1fms  설명력 %5.1f%%  회전각 %.2f deg"
          % (fc, lag*1e3, 100*qq, rot_angle(R)))
```

**결과**

| 대역 | 최적 지연 | 설명력 | 회전각 |
|---|---|---|---|
| 2 Hz | −6 ms | **98.0%** | 173.30° |
| 5 Hz | −7 ms | 97.1% | 173.28° |
| 20 Hz | −8 ms | 94.0% | 173.34° |
| 40 Hz | −8 ms | 90.7% | 173.38° |

### 함정 — 대역폭 정합

**두 IMU의 내부 필터 대역이 다르면 위상이 어긋나 설명력이 깎인다.** 처음에 필터 없이 돌렸을 때 87.7%가 나와 추정을 의심했으나, 2 Hz로 맞추니 98.0%가 됐다. **서로 다른 센서를 정렬할 때는 대역폭을 먼저 맞출 것.**

### 안정성 확인

시간 창을 쪼개 독립적으로 추정하고 일치하는지 본다.

```python
A0 = prep(t, g, 5); B0 = prep(lt, lg, 5, -0.008)
ed = np.linspace(0, len(grid), 9).astype(int)
for i in range(8):
    sl = slice(ed[i], ed[i+1]); s = np.linalg.norm(A0[sl], axis=1) > 0.4
    if s.sum() < 200: continue
    R, qq = kabsch(A0[sl][s], B0[sl][s])
    print("창%d n=%4d 설명력 %.1f%% 회전각 %.2f deg" % (i+1, s.sum(), 100*qq, rot_angle(R)))
```

7개 창 전부 설명력 96.9~97.9%, yaw 성분 −126.9° ~ −128.4°로 일치 → **확정**.

**판정 기준:** 설명력 95% 이상, 창별 편차 3° 이내면 신뢰. 그 이하면 대역폭·시간정렬을 먼저 의심한다.

## 검증 7 — LIO 결과 평가

알고리즘 출력(`/aft_mapped_to_init`)을 `robot_odom` 기준선과 비교한다.

먼저 CSV로 뽑는다.

```python
# dump_odom.py 와 동일. Bag 클래스로도 가능:
Bo = Bag('plio_out_0.db3')
ft, fp, fq = Bo.odom('/aft_mapped_to_init'); ft -= T0
```

```python
rs = [('R2',15.72,18.49), ('R3',27.69,30.51), ('R6',38.15,40.66),
      ('R8',46.48,49.34), ('R9',51.34,53.73), ('R14',85.47,89.23)]
print("총 경로 %.2f m (참값 32.5) | 루프클로저 %.3f m (참값 0.56)"
      % (np.linalg.norm(np.diff(fp[:,:2],axis=0),axis=1).sum(),
         np.linalg.norm(fp[-1,:2]-fp[0,:2])))
tt = np.arange(0.5, 109, 0.05)
gz = np.interp(tt, ot, op[:,2]); gz -= gz[0]
fz = np.interp(tt, ft, fp[:,2]); fz -= fz[0]
e = fz - gz
print("z RMSE %.1f mm | 최대 %.1f mm | 최종 %+.1f mm"
      % (1e3*np.sqrt((e**2).mean()), 1e3*np.abs(e).max(), 1e3*e[-1]))
for nm, s, en in rs:
    gg = 1e3*(np.interp(en,ot,op[:,2]) - np.interp(s,ot,op[:,2]))
    ff = 1e3*(np.interp(en,ft,fp[:,2]) - np.interp(s,ft,fp[:,2]))
    print("  %-4s 참값 %+6.1f mm  결과 %+7.1f mm  차이 %+7.1f mm" % (nm, gg, ff, ff-gg))
```

**판정 기준**

| 지표 | 참값 | 양호 | 불량 |
|---|---|---|---|
| z RMSE | — | < 50 mm | > 200 mm |
| 최종 z 오차 | 1.8 mm | < 30 mm | > 100 mm |
| 루프 클로저 | 0.56 m | < 1.0 m | > 2 m |
| 수평 총거리 | 32.5 m | 30~36 m | > 40 m |
| 회전 구간별 z | ±6 mm | 차이 < 30 mm | > 100 mm |

**발산 시점 찾기** — 실패했을 때는 언제 터졌는지가 원인을 가리킨다.

```python
r = np.linalg.norm(fp, axis=1)
for th in [1, 10, 100]:
    k = np.argmax(r > th)
    if r.max() > th: print("|pos| > %d m 최초 t=%.2f s" % (th, ft[k]))
```

이번 사례에서 두 실행 모두 t=7.79 s에서 터졌고, 그것이 **첫 회전 구간 R0(6.65~7.94 s) 한가운데**라는 사실이 "회전 관련 문제"로 범위를 좁혀 주었다.

```
  ↓
검증 7  결과 평가 + 발산 시점   ← 증상을 시간축에 고정
  ↓

  ↓
검증 1  정지 중력·바이어스      ← 싸고 빠름
검증 5  좌표계 정합            ← extrinsic 확인 (부호 주의!)
  ↓
검증 4  가속도계 유효성        ← 결정적. 1·5가 통과해도 여기서 걸릴 수 있음
  ↓
검증 6  외부 파라미터 추정      ← 수정값 산출 (대역폭 정합 필수)
```

## 이번에 겪은 함정

- **좌표계 부호는 데이터 분포로 확인할 것.** RANSAC 법선은 부호를 주지 않는다. 클라우드 좌표의 분포를 먼저 본다.
- **서로 다른 센서를 정렬할 때는 대역폭을 맞출 것.** 위상차만으로 설명력이 10%p 넘게 깎인다.
- **평균과 상관은 다르다.** 회전을 결정하는 것은 벡터쌍의 상관이다.
- **정지 검증만으로 IMU를 신뢰하지 말 것.** 그럴듯한 중력 벡터를 뱉으면서 실제 운동은 전혀 못 따라갈 수 있다. 검증 4가 필요한 이유다.
- **실측된 이상이 곧 원인은 아니다.** `acc_norm` +6.4% 스케일 오차는 사실이었지만 발산의 원인이 아니었다. 가설이 틀렸으면 빨리 버린다.
