# 실험 3 결과 — 움직임 중 RMSE (정확도)

## 실험 개요

각 IMU(L1, body, fix)의 가속도 "값 크기"가 실제와 얼마나 맞는지를
오도메트리 기준으로 RMSE(평균제곱근오차)로 측정한다.

- **날짜:** 2026-08-18
- **데이터:** 실험 2와 **동일한 CSV** (`exp2_v2.csv`) 재사용 — 새로 측정하지 않음.
- **이유:** RMSE와 상관계수는 같은 데이터를 보는 두 각도다.
  - 실험 2(상관): IMU가 실제 움직임을 **따라가나** (패턴 동조)
  - 실험 3(RMSE): IMU 값이 실제와 **크기가 맞나** (값 정확도)

### 상관 vs RMSE — 왜 둘 다 필요한가

상관계수는 값이 배수로 틀려도 패턴만 맞으면 높게 나온다(크기를 못 본다).
그래서 "크기까지 정확한가"는 RMSE로 따로 확인해야 한다. 두 지표는 보완 관계다.

## 사용한 수식

### 기호 설명 (수식에 쓰인 미지수)

| 기호 | 의미 | 비고 |
|---|---|---|
| `a_IMU` | IMU가 잰 가속도 (world, 중력 제거 후) | m/s² |
| `a_real` | odom으로 만든 실제 가속도 (world) | 채점 기준 |
| `N` | 비교한 샘플 개수 | |
| `Σ` | 합(시그마) — 모든 샘플에 대해 더함 | |
| `R_odom` | 로봇 자세 회전행렬 (base_link → world) | odom 쿼터니언에서 |
| `R_LB` / `R_LBᵀ` | base_link↔LiDAR 프레임 회전 / 그 역 | 실험 1·2와 동일 |
| `offset` | 정지 구간 world 가속도 평균 (= 중력+bias) | 이걸 빼서 운동가속도만 남김 |
| RMSE | 평균제곱근오차 (Root Mean Square Error) | 작을수록 정확 |

### ① 중력 제거 — 운동 가속도만 남기기

IMU는 중력 + 운동 가속도를 함께 잰다. RMSE는 "운동"만 비교해야 하므로,
정지 구간(초기 0~15초)의 world 가속도 평균을 각 소스의 오프셋으로 잡아 뺀다.

```
a_IMU(운동) = a_IMU(world) − offset
offset = (정지 구간 world 가속도의 평균)
```

### ② RMSE (평균제곱근오차)

IMU 가속도와 실제 가속도의 차이를 제곱해 평균낸 뒤 제곱근.

```
RMSE = sqrt( mean( (a_IMU − a_real)² ) )
```

풀어 쓰면:

```
1. 오차      : e = a_IMU − a_real        (매 샘플)
2. 제곱      : e²
3. 평균      : (1/N) · Σ e²
4. 제곱근    : RMSE = √( (1/N) · Σ e² )
```

- 축별로 각각 구하고, 3D는 세 축 오차를 합쳐 구한다.
- 값이 작을수록 실제와 가까움 = 정확.

### 프레임·미분 처리

실험 2와 동일하다. IMU 가속도는 프레임 정렬(body는 R_odom, L1·fix는
R_odom·R_LBᵀ)로 world로 옮기고, 실제 가속도는 odom 속도의 1차 미분(A안)을 쓴다.

## 결과

### 전체 움직임 구간 (t=17~72) — RMSE (m/s²)

| source | x | y | z | 3D |
|---|---|---|---|---|
| body | 1.163 | 1.096 | 1.330 | 2.079 |
| **fix** | 1.150 | 1.091 | 1.318 | **2.062** |
| L1 | 2.863 | 3.620 | 3.294 | **5.670** |

- **fix ≈ body, 심지어 fix가 미세하게 더 정확** — fix는 body 가속도에 스케일
  보정(×1.036)을 하므로 크기가 살짝 더 맞다.
- **L1은 body의 약 2.7배 부정확** (5.670 vs 2.079).

### 구간별

| 구간 | source | 3D RMSE |
|---|---|---|
| 가다서다 (17~51) | body | 1.680 |
| | fix | 1.668 |
| | L1 | 3.184 |
| 원/곡선 (51~72) | body | 2.599 |
| | fix | 2.575 |
| | L1 | **8.235** |

→ 모든 구간에서 fix ≈ body. L1은 특히 **원/곡선(회전)에서 3배 이상**(8.235 vs 2.599)
   벌어진다. 회전할 때 L1이 가장 심하게 틀린다.

### 상관(실험 2) 대비 — RMSE가 더 뚜렷하다

- 실험 2 상관: L1 z=0.14 vs body z=0.40 (격차 있으나 절대값이 낮아 애매)
- 실험 3 RMSE: L1 5.67 vs body 2.08 (**2.7배**, 훨씬 뚜렷)

상관은 "패턴"만 봐서 L1의 크기 오차를 놓쳤지만, RMSE는 "크기 차이"를 보므로
L1이 크기부터 +8% 틀리고 방향도 142° 틀린 것(실험 1)이 그대로 크게 찍혔다.

## 결론

1. **fix는 크기(정확도)까지 정상** — RMSE가 body와 동일하거나 미세하게 더 작음.
   스케일 보정 덕분에 body보다도 살짝 정확.
2. **L1은 고장 재확인** — body의 약 2.7배 부정확, 회전에서는 3배 이상.
3. **RMSE가 상관보다 L1 고장을 뚜렷하게 드러냄** — 크기 오차를 직접 보기 때문.

### 한계 (정직하게)

- **RMSE 절대값이 크다** (body 2.08 > 실제가속도 RMS 1.01). 이는 body가
  부정확해서가 아니라, **채점 기준(odom 실제 가속도) 자체가 노이즈가 심하기
  때문**이다(실험 2와 동일 원인).
- 따라서 판단은 절대값이 아니라 **소스 간 상대 비교**로 한다.
  fix≈body / L1은 배수로 큼 — 이 관계는 명확하다.
- odom 정답지의 신뢰도는 **실험 4**에서 정식으로 다룬다.

### fix 검증 종합 (실험 1 + 2 + 3)

| 실험 | 보는 것 | fix | L1 |
|---|---|---|---|
| 1 (정지) | 크기·방향 | 완벽 (0.25%, 0°) | 고장 (142.6°) |
| 2 (동적) | 상관(동조) | ≈ body | << body |
| 3 (동적) | RMSE(정확도) | ≈ body (약간 더 정확) | body의 2.7배 |

→ **세 실험 모두 같은 결론: fix 정상, L1 고장.**
"fix가 부분 수리이고 Point-LIO가 가려준 것"이라는 의심은 정적·동적·크기·방향
어느 검증에서도 근거가 나오지 않았다. **fix 자체는 정상**이며, 다른 알고리즘에서의
발산 원인은 fix가 아니라 다른 곳에서 찾아야 한다.

`analyze_exp3.py`로 저장하고 `PATH`만 바꿔 실행하면 재현된다.

```python
# 1) 실험 2와 동일하게 프레임 정렬해서 IMU 가속도를 world 로

# 2) 중력 제거: 정지구간(0~15s) world 가속도 평균(offset)을 빼기
# 3) 실제 가속도: odom 속도 1차미분 (A안)
# 4) RMSE = sqrt(mean((a_IMU - a_real)^2))  축별 + 3D
```

### 판정 기준

| 무엇을 보나 | 판정 |
|---|---|
| fix 정상 여부 | fix RMSE ≈ body RMSE 이면 정상 |
| L1 고장 정도 | L1 RMSE >> body RMSE (배수로 크면) 고장 |

> **주의:** RMSE 절대값(2.08 등)이 크다고 body가 부정확한 게 아니다.
> odom 기준의 노이즈 탓이며, 판단은 **소스 간 상대 비교(배수)**로 한다.
