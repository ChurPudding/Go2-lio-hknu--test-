# loop_0810 녹화 절차

2026-08-10 · Go2 X 실내 전체 매핑

## 목적

구석구석 훑는 전체 경로로 한 번에 지도를 만든다. 이후 `loop_correct_v2.py`
(축척계수 k=1.1995 패치 적용) → `pcd_to_grid.py` 로 3D 점군과 A* 용 격자를 만든다.

```bash
df -h ~/data
```

줄어들었고 배터리 영향으로 추정된다. 나중에 비교할 때 근거가 된다.

## 터미널 2 — 녹화

```bash
source ~/setup_go2.sh
cd ~/data/bags/indoor
ros2 bag record -o loop_0810 \
  /utlidar/cloud /utlidar/cloud_deskewed /utlidar/robot_odom \
  /utlidar/imu /sportmodestate
```

| 토픽 | 용도 |
|---|---|
| `/utlidar/cloud` | 단일 프레임. 나중에 디스큐 직접 구현할 때 |
| `/utlidar/cloud_deskewed` | 이번 지도 생성용 (이미 odom 좌표계) |
| `/utlidar/robot_odom` | 자세. 축척 보정과 루프 클로저의 입력 |
| `/utlidar/imu` | 진단용. 용량 부족하면 제외 가능 |
| `/sportmodestate` | 내부 융합 자세 |

10분 녹화 시 4~5 GB.

## 터미널 3 — RViz (선택)

```bash
source ~/setup_go2.sh
ros2 run tf2_ros static_transform_publisher 0 0 0 0 0 0 map odom &
rviz2
```

- Fixed Frame → `odom`
- Add → PointCloud2 → Topic `/utlidar/cloud_deskewed`
- Decay Time → `120`
- 무거우면 Size `0.02`, Style `Points`

축척 보정도 루프 클로저도 안 들어간 원본이다. 정확도 판단용이 아니라
"기둥이 두 개로 보이는가" 같은 눈에 띄는 문제만 잡는 용도.

## 주행 순서

1. 남쪽 중앙 3면 자리에 **북향**으로 세운다. 뒤 모서리를 타일 줄눈에 맞춘다
2. 녹화 시작 → **3초 정지**
3. 오른쪽 아래 방 — 기둥 한 바퀴 → 방 벽 따라 한 바퀴
4. 북상하며 엘리베이터 공간 훑기
5. 반원 방에서 **곡선** 유턴
6. 남하하며 엘리베이터 공간 다시 훑기
7. 오른쪽 아래 방 — 기둥 한 바퀴 → 방 벽 따라 한 바퀴
8. 출발 자리 복귀 → **3초 정지** → `Ctrl+C`

약 250~300 m, 8~10분.

### 지킬 것

- **좁은 곳에서 서서 돌지 않는다.** 방향 전환은 넓은 곳에서 곡선으로.
  서서 돌아야만 하는 자리가 나오면 그 구간을 포기하고 지나간다
- 복도에서는 벽과의 거리를 일정하게 유지
- 앞뒤 3초 정지는 필수. 시작·끝 자세를 깨끗하게 읽어야 루프 클로저가 맞는다
- 돌아와서 출발 자리에서 **타일 몇 칸 어긋났는지** 센다.
  스크립트가 계산한 폐쇄 오차와 대조할 유일한 외부 기준

## 처리 (녹화 후)

```bash
cd ~/fastlio_ws/tools

python3 loop_correct_v2.py ~/data/bags/indoor/loop_0810 \
        --out ~/fastlio_ws/results/loop_0810

python3 pcd_to_grid.py ~/fastlio_ws/results/loop_0810/scans.pcd \
        ~/fastlio_ws/results/loop_0810/grid 0.10
```

출발 자세와 도착 자세가 반대이면 `--end-dyaw 180` 을 붙인다.
이번 경로는 북향으로 출발해 북향으로 도착하므로 **옵션 없이** 맞다.

### 볼 것

| 항목 | 기준 |
|---|---|
| `[2] 보정할 오차` | 실제로 센 타일 칸수와 맞는가 |
| `[6] 전반/후반 겹침` | v2 는 0.45 m 였다 |
| ICP RMSE | 낮을수록 정합 신뢰도 높음 |
| `장애물 칸 비율` | v3 는 8.1% 였다 |

### 검증

```bash
python3 map_measure.py ~/fastlio_ws/results/loop_0810/grid.yaml --actual 10.45
python3 yaw_check.py ~/data/bags/indoor/loop_0810
```

- 지도 거리: 수직 구간이 10.45 m 근처로 나와야 한다
- `yaw_check.py` 의 **회전 구간 개수**: 지난 bag 은 31개였다.
  0~5개면 의도대로 곡선으로 걸은 것. 20개가 넘으면 조금씩 서서 돈 것이므로
  "회전을 줄이면 지도가 좋아진다" 가설은 이 bag 으로 검증할 수 없다
