# 2026-08-10 실험기록 — 축척계수 확정 및 경로 설계로 루프 폐쇄 0.27% 달성

## 요약

아침 상태는 "지도가 얼마나 정확한지 모른다"였다. 하루 동안 세 가지가 확정됐다.

1. **다리 오도메트리는 거리를 17% 짧게 잰다.** 축척계수 k = 1.1995
2. **다리 오도메트리의 회전은 정확하다.** 회당 0.17도
3. **경로 설계만 바꿔서 루프 폐쇄 오차가 2.63% → 0.27%로 줄었다.** 코드 변경 없음

가설 두 개를 데이터로 기각했고, 벽 번짐의 원인 후보를 하나로 좁혔다.

정본 산출물: `results/loop_0810/`

## 1. 축척계수 측정

### 실측 기준

바닥 타일 한 변 40 cm 를 세는 방식. 줄자를 여러 번 옮기며 생기는 누적 오차가 없다.

| 구간 | 칸 수 | 실측 |
|---|---|---|
| 복도 왕복 주행 거리 | 128칸 + 63 cm* | **51.83 m** |
| 복도와 수직 방향 (좌측 구역 서벽 → 복도 동벽) | 25칸 + 45 cm | **10.45 m** |
| 좌측 구역 폭 | 20칸 + 8 cm | 8.08 m |
| 복도 폭 | 5칸 + 37 cm | **2.37 m** |

\* 중간에 규격이 다른 칸이 하나 있어 따로 실측.
8.08 + 2.37 = 10.45 로 세 값이 자기들끼리 일치 → 측정 신뢰도 확인.

기준점은 **로봇 몸통의 같은 모서리**를 출발·도착에서 사용. 앞뒤 모서리를 섞으면
몸길이(약 70 cm)만큼 통째로 틀어진다.

### 결과 (`tools/scale_check.py`)

`scale_0810_run1~3` (전진), `run1~3_back` (후진), 각 51.83 m 구간.

| | 직선 변위 평균 | 편차 | 축척계수 |
|---|---|---|---|
| 전진 3회 | 43.284 m | 0.376 m | 1.1975 |
| 후진 3회 | 43.126 m | 0.261 m | 1.2019 |
| **통합 6회** | **43.21 m** | **0.33 m** | **1.1995** |

- **방향 의존성 없음.** 전진·후진 차이 0.37%. z 변화 1.4 cm 이하로 경사 아님
- 직진성 양호. 경로장이 직선 대비 +1.3~2.3%, yaw 변화 5도 이내
- **6회가 순서대로 단조 감소** (43.811 → 42.877, 총 2.1%).
  배터리 전압 강하로 보폭이 줄어든 것으로 추정. 실험 시 배터리 조건을 맞출 것

### 검증

`floor_0805_1720` (8월 5일 녹화, 다른 세션·다른 경로)에 k = 1.1995 를 적용한 결과,
수직 구간이 9.072 m → **10.460 m** (실측 10.45 m 대비 **0.10%**).
다른 날 데이터에서 검증됐으므로 세션 의존적인 값이 아니다.

## 2. 회전 정확도 (`tools/yaw_check.py`)

### 자이로는 `R_BL` 변환이 필수다

`/utlidar/imu` 의 `angular_velocity` 는 LiDAR 프레임 값이다.
`go2_calib.py` 의 `R_LB[2,2] = -0.964721` 이므로

- 부호가 반대 (라이다 z 가 아래를 향함)
- 크기가 0.9647 → **생짜 z 를 쓰면 회전량을 3.5% 적게 읽는다**

`R_BL` 을 곱해 base_link 프레임으로 돌리면 A/B 비가 1.0313 → **1.0057** 로 붙는다.
예측값 1/0.964721 = 1.0366 과 부합.

### 결론

`floor_0805_1720` 회전 구간 31회:

- **A/B 평균 1.0057** — 다리 오도메트리 회전은 정확
- **누적 차이 +5.25도** (회당 0.17도) — 좌우 회전이 상쇄되어 전역 방향은 거의 안 틀어짐
- 편차 0.0374 — 일부 구간에서 5~9도 튐 (121.7초 0.875, 318.5초 1.126)

**정리: 다리 오도메트리는 거리는 17% 짧게 재지만 각도는 정확하다.**
축척 부족은 발 미끄러짐으로 보폭이 짧게 계산되는 문제이고,
회전은 네 다리의 상대 위치로 결정되므로 미끄러짐 영향을 덜 받는 것으로 해석된다.

### 주의: 총 회전량 비교는 무효

`ω_z` 를 그대로 적분하면 몸통이 수평일 때만 요 변화율과 같다.
걷는 동안 피치·롤이 흔들리므로 누적 오차가 쌓인다 (442초에 244도).
**구간별 비교(1~2초)는 유효, 총 회전량 비교는 무효.**

## 3. 기각된 가설 — 벽 번짐의 원인

`odommap_v2` 의 벽 두께 약 0.4 m. 원인 후보 셋 중 둘을 기각했다.

### 가설 A: 축척 부족 → **기각**

축척이 부족하면 같은 벽이 두 곳에 찍힌다는 논리였다.
k = 1.1995 를 적용해 `odommap_v3` 를 만들었으나 장애물 칸 비율 8.0% → 8.1% 로 변화 없음.
거리는 0.10% 로 맞았지만 벽은 두꺼워지기만 했다.

단, 이 비교는 조건이 둘 다 달랐다 (v2 = 무축척+루프보정, v3 = 축척+무루프보정).
엄밀한 재검증이 필요하나, 이후 `loop_0810` 에서 축척을 적용하고도
벽 두께가 남은 것으로 보아 결론은 유지된다.

### 가설 B: 회전 중 요 오차 → **주원인 아님**

제자리 회전 중 5~12도 오차가 실제로 있고, 5 m 거리의 기둥이 1 m 옮겨 보인다.
(RViz 실시간 확인에서 관측됨)

그러나 442초 중 회전 구간은 30초 남짓(7%)뿐이다.
나머지 93%의 직진 구간에서는 요가 안정적이므로,
지도 전체를 0.4 m 두께로 번지게 하는 원인은 못 된다.

### 남은 후보: `cloud_deskewed` 프레임 누적

같은 프레임을 나란히 비교한 결과:

```
/utlidar/cloud            4,107 점   frame_id: utlidar_lidar
/utlidar/cloud_deskewed  11,562 점   frame_id: odom     → 2.815 배
```

세 스캔치를 겹쳐 내보내고 있다. 이전 프레임 점이 현재 자세로 놓이면서 번짐이 생긴다.

**다음 작업의 재료는 확보됨:**

- `/utlidar/cloud` 에 `time` 필드 존재 (offset 24, float32) → 점별 디스큐 가능
- `ring` 필드도 있음
- `R_LB`, `LEVER` = `go2_calib.py`
- 회전 정확도 회당 0.17도 → 스캔 66 ms 동안의 자세를 신뢰 가능
- 축척계수 1.1995

목표: 벽 두께 0.4 m → 0.15 m 이하. 안 되면 이 방향은 접는다.

## 4. 경로 설계 — 가장 큰 효과

코드 변경 없이 **걷는 방식만 바꿔서** 루프 폐쇄 오차가 10분의 1이 됐다.

| | `floor_0805_1720` | `loop_0810_1` |
|---|---|---|
| 주행 시간 | 442 s | 523 s |
| 총 이동 | — | 211.2 m |
| 회전 구간 | 31회 | **19회** (경로는 15% 길어짐) |
| 루프 폐쇄 오차 | 2.63% | **0.58 m / 211.2 m = 0.27%** |
| 끝 방향 오차 | — | −1.7도 |
| 장애물 칸 비율 | 8.0% | **7.7%** |
| 전반/후반 겹침 | 0.45 m | 0.67 m (경로가 달라 직접 비교 어려움) |

### 지킨 원칙

1. **좁은 곳에서 서서 돌지 않기.** 방향 전환은 넓은 곳에서 곡선으로
2. **출발·도착은 3면이 보이는 막다른 곳.** ICP 정합이 미끄러지지 않는다
3. **같은 공간을 갈 때·올 때 두 번 훑기.** 관측이 겹치면 지도가 스스로를 검증한다

3번이 특히 유효했던 것으로 보인다.

### 경로 (건물 구조)

- 남쪽 중앙 3면 지점 출발 (북향)
- 오른쪽 아래 방 — 기둥 한 바퀴 → 방 벽 따라 한 바퀴
- 북상하며 엘리베이터 공간 훑기
- 반원 방(계단)에서 곡선 유턴
- 남하하며 엘리베이터 공간 다시
- 오른쪽 아래 방 반복 → 출발 자리 복귀

건물은 나뭇가지 구조로 닫힌 고리가 없다. 유일한 고리는 아래쪽 방의 기둥 주위.

### 남은 이상치

190.3초 구간에서 A/B = 0.628 (11.7도 오차). 하루 중 최악.
전체 편차가 0.0374 → 0.0990 으로 커진 주범.
경로가 복잡해지면 이런 순간이 늘어나므로, 상보 필터(자이로 + 다리 오도메트리)로
억제하는 방안은 여전히 유효하다.

### 새 도구

| 파일 | 용도 |
|---|---|
| `tools/scale_check.py` | bag 앞뒤 정지 구간을 자동 검출해 직선 변위·경로장 계산. `--actual` 로 축척계수 산출 |
| `tools/map_measure.py` | `grid.pgm` 에서 두 점 클릭으로 거리 측정. 회전된 지도에서도 유효 |
| `tools/yaw_check.py` | 다리 오도메트리 요 vs 자이로 적분 vs 내부 융합 비교. 회전 구간 자동 검출 |
| `tools/odom_map_build_v2.py` | 궤적에 축척계수 적용. `p' = p + (k−1)·t(t)` |
| `tools/loop_correct_v2.py` | `--k` 옵션 추가 (기본 1.1995) |

### 축척 적용 원리

`cloud_deskewed` 의 점은 이미 odom 좌표계이므로

```
p_odom(t) = R(t)·p_body + t(t)
```

축척 오차는 로봇 위치 `t(t)` 에만 있다. `R(t)` 는 자이로 적분, `p_body` 는 라이다 참값.
따라서 각 프레임에 `(k−1)·t(t)` 를 더하면 궤적만 늘어나고 스캔 모양은 보존된다.
좌표 변환도 레버암도 필요 없다.

`k−1 = 0.2` 이므로 타임스탬프가 50 ms 어긋나도 오차 0.5 cm.
라이다 클록이 20.7초 밀린 문제를 신경 쓰지 않아도 된다.
