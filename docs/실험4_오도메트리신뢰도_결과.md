# 실험 4 결과 — 오도메트리 신뢰도 분석

## 실험 개요

실험 2·3에서 채점 기준(정답지)으로 쓴 오도메트리(odom)가 얼마나 믿을 만한지,
그리고 그 오차가 어디서 오는지를 분석한다.

- **날짜:** 2026-08-18
- **데이터:** `exp2_v2.csv` (실험 2·3와 동일) + 검증용 `exp2_check.csv` (락 없이 재측정)
- **왜 필요한가:** 실험 2·3의 상관·RMSE 절대값이 낮았고, 그 원인을 "odom 자체가
  노이즈"로 추정했다. 이 추정을 실제로 확인한다.

### 방법의 한계 — odom을 뭘로 채점하나

odom보다 더 믿을 만한 외부 기준이 없다(odom이 가장 독립적인 참조였다).
따라서 "정답 대비 오차"를 직접 못 재고, **간접 방법**으로 신뢰도를 본다.

- **내부 일관성:** odom은 위치(pose)와 속도(twist)를 둘 다 준다. 위치를 미분한
  속도와 twist 속도가 서로 맞아야 정상이다. 어긋나면 odom 내부 모순 = 노이즈.
- **정지 vs 움직임 대조:** 정지 시 얼마나 조용한지 vs 움직일 때 얼마나 튀는지.

## 사용한 수식

### 기호 설명

| 기호 | 의미 | 비고 |
|---|---|---|
| `p` | odom 위치 (pₓ, p_y, p_z) | m |
| `v_twist` | odom이 준 속도(twist) | base_link 프레임 |
| `v_pos` | 위치를 미분해 얻은 속도 | v_pos = dp/dt |
| `R_odom` | 로봇 자세 회전행렬 (base_link → world) | odom 쿼터니언에서 |
| `w` (wₓ,w_y,w_z) | odom 각속도(twist angular) | rad/s |
| `RMS` | 제곱평균제곱근 (신호 세기) | √(mean(값²)) |

### ① 내부 일관성 — 위치 미분 vs twist

**왜 이 방법을 골랐나:**
odom을 채점할 외부 기준(더 정확한 참조)이 없다. 그래서 "정답과 비교"가 불가능하다.
대신 odom이 **위치(pose)와 속도(twist)를 둘 다 제공**한다는 점을 이용한다.
이 둘은 원래 같은 움직임을 다르게 표현한 것이므로, 물리적으로 반드시 맞아야 한다:

> 위치를 시간 미분하면 속도가 된다 (v = dp/dt).
> 그러므로 "위치를 미분한 속도"와 "odom이 직접 준 속도(twist)"는 같아야 한다.

둘이 어긋나면, 그건 **odom 내부의 두 추정이 서로 모순**된다는 뜻이고,
외부 기준 없이도 "odom이 그 순간 신뢰할 수 없다"를 잡아낼 수 있다.
이것이 외부 정답지 없이 신뢰도를 보는 표준적 방법이다.

```
v_pos          = dp/dt                 (위치를 미분한 속도)
v_twist_world  = R_odom · v_twist      (twist를 world 프레임으로 회전)
불일치          = | v_pos − v_twist_world |
```

**왜 R_odom을 곱하나:** v_twist는 base_link(로봇 몸통) 프레임인데, v_pos는 world
프레임(위치가 world 기준이므로)이다. 프레임이 다르면 같은 속도라도 값이 다르게
나오므로, twist를 R_odom으로 회전해 world로 맞춘 뒤에 비교한다.

**불일치=0이 이상적인 이유:** 완벽한 odom이라면 두 표현이 정확히 일치(불일치 0)한다.
불일치가 클수록 그 순간 odom의 위치·속도 추정이 따로 놀고 있다는 신호다.

### ② 노이즈 수준 — 실제 가속도의 RMS (스무딩 전후 비교)

**왜 이 방법을 골랐나:**
실험 2·3에서 상관·RMSE 절대값이 낮았고, 그 원인을 "odom을 미분해 만든 실제
가속도가 지저분하다"로 추정했다. 이 추정을 수치로 확인해야 한다. 그런데 노이즈는
직접 "이만큼이 노이즈"라고 떼어낼 수 없다. 대신 **스무딩(평활화)의 성질**을 이용한다:

> 스무딩은 빠르게 흔들리는 성분(노이즈)을 지우고, 천천히 변하는 성분(진짜 신호)을 남긴다.
> 그러므로 "스무딩 전(raw)"과 "스무딩 후(smooth)"의 차이가 곧 노이즈의 양이다.

```
RMS = √( mean( |a|² ) )        (신호의 세기)
```

**RMS를 쓰는 이유:** 가속도는 +/-로 진동해서 그냥 평균내면 0에 가까워 세기를 못 잰다.
제곱해서 평균내면(RMS) 부호가 사라지고 "얼마나 큰 값이 오가는지"의 세기가 나온다.

**해석 규칙:**
- raw RMS ≫ smooth RMS → 그 차이만큼이 노이즈였다 (신호 대부분이 노이즈).
- raw RMS ≈ smooth RMS → 노이즈가 적고 대부분 진짜 신호.
- **정지 구간에서도 raw RMS 계산:** 정지면 실제 가속도는 0이어야 하므로,
  정지 구간의 RMS는 **순수 노이즈의 양**을 직접 보여준다 (기준점 역할).

### 왜 "구간별"로 나눠 보나

odom 오차의 **원인**을 찾으려면, 어떤 상황에서 나빠지는지를 봐야 한다.
정지/가다서다/원곡선으로 나눠 각각의 불일치를 비교하면:
- 정지에서 조용하고 움직임에서 나빠지면 → 원인은 "움직임"에 있다.
- 각속도(회전)가 클수록 나빠지면 → 원인에 "회전"이 크게 기여한다.

즉 구간 분리는 "언제 나쁜가"를 통해 "왜 나쁜가"를 역추적하는 장치다.

## 결과

### 1) 내부 일관성 (불일치, m/s)

| 구간 | 평균 | 최대 |
|---|---|---|
| 정지 (2~15) | 0.032 | 0.05 |
| 가다서다 | 0.038 | 1.15 |
| 원곡선 (51~72) | 0.071 | 1.35 |

- **평균은 작다**(0.03~0.07) → odom은 대체로 내부 일관성이 있다. 통째로 엉터리는 아니다.
- **최대는 튄다**(1~1.3) → 움직임 순간마다 순간 스파이크가 있다.

### 2) 정지 구간 노이즈

| 항목 | 정지 시 표준편차 |
|---|---|
| 선속도 (vₓ, v_y, v_z) | (0.007, 0.007, 0.001) |
| 각속도 (wₓ, w_y, w_z) | (0.007, 0.007, 0.006) |

→ 정지 상태에서 odom은 아주 조용하다. **정지 시 odom은 믿을 만하다.**

### 3) 실제 가속도 노이즈 (스무딩 전후)

| 구간 | raw RMS | smooth RMS |
|---|---|---|
| 움직임 (17~72) | 8.533 | 1.009 |
| 정지 (2~15) | 1.077 | 0.073 |

- **움직임 시 raw 8.5 → smooth 1.0** = raw의 약 88%가 노이즈였다.
  → **실험 2·3의 상관·RMSE 절대값이 낮았던 것은 odom 기준의 이 노이즈 탓임이 확증됨.**
- 정지 시엔 raw도 1.0 수준 → 움직일 때만 지저분해진다.

### 4) 주오차 원인 — 움직임 유형별

| 구간 | 불일치 평균 | 평균 각속도 |
|---|---|---|
| 정지 | 0.032 | 0.005 |
| 가다서다 | 0.038 | 0.028 |
| 원곡선 | 0.071 | 0.926 |

→ **각속도가 클수록(회전할수록) 불일치가 커진다.** 회전에서 odom이 가장 지저분하다.

## 락(lock) 이벤트 검증 — 스파이크 재현 실험

### 배경

`exp2_v2.csv`에서 t=20.37초에 유독 큰 스파이크(불일치 4.45)가 있었다.
분석 중 이를 "정지→운동 전환 충격"으로 해석했으나, 측정자가 그 순간
**움직임 락(lock)을 걸었다가 앞으로 안 가서 풀고 출발**했음이 확인되었다.

→ 스파이크가 락 때문인지 확인하기 위해, **락 없이 깨끗하게** 가다 서다를
   재측정했다 (`exp2_check.csv`).

### 결과

| 측정 | 첫 출발 스파이크 |
|---|---|
| `exp2_v2` (락 있음) | 4.45 @ t=20초 |
| `exp2_check` (락 없음) | **2.21 @ t=17초** |

**두 가지가 밝혀졌다:**

1. **락은 스파이크를 약 2배 키웠다** (2.2 → 4.5). 측정자의 기억이 맞았다.
2. **락 없이도 첫 출발에 2.2의 스파이크가 있다.** 즉 스파이크는 락만의 문제가
   아니라, **정지→운동 전환 자체가 원래 튀는 odom 특성**이다.

→ 진짜 원인 = "출발 순간 전환 튐"(기본, ~2) + "락 풀림 충격"(추가, +2.3)이 겹친 것.

> **방법론적 의미:** 이상값의 원인을 측정자 기억("락 때문")으로만 결론짓지 않고
> 재측정으로 검증하니, "락 + 전환 튐 둘 다"라는 더 정확한 답이 나왔다.
> 재측정하지 않았다면 "순전히 락 탓"이라는 부분적으로 틀린 결론을 낼 뻔했다.

## 결론

1. **odom은 정지 시 믿을 만하다** — 내부 불일치 0.03, 노이즈 표준편차 0.007.
2. **움직임 전환(출발) 순간마다 스파이크가 있다** (~2, odom 자체 특성).
   락 같은 조작 이벤트는 이를 더 키운다.
3. **회전에서 가장 지저분하다** — 각속도가 클수록 내부 불일치 증가(원곡선 0.071).
4. **실험 2·3 해명 확증** — 움직임 시 odom 실제가속도의 약 88%가 노이즈(raw 8.5 →
   smooth 1.0). 상관·RMSE 절대값이 낮았던 것은 fix가 아니라 **odom 기준의 노이즈 탓**.

### fix 검증 종합 (실험 1~4 완결)

| 실험 | 보는 것 | 결과 |
|---|---|---|
| 1 | 정지 크기·방향 | fix 완벽 / L1 고장(142.6°) |
| 2 | 동적 상관(동조) | fix ≈ body / L1 << body |
| 3 | 동적 RMSE(정확도) | fix ≈ body / L1 body의 2.7배 |
| 4 | odom 신뢰도 | 절대값 낮음은 odom 노이즈 탓, fix 아님 |

→ **최종: fix는 정상.** 정적·동적·크기·방향 어느 검증에서도 fix 문제 근거 없음.
   실험 2·3의 낮은 절대값도 odom 노이즈로 설명됨(실험 4). "fix가 부분 수리이고
   Point-LIO가 가려준 것"이라는 의심은 근거가 없다. **fix를 믿고 본 실험(Point-LIO
   오차 감소)으로 진행할 수 있다.**

### 본 실험에 대한 함의

- odom을 Point-LIO 비교 기준으로 쓸 때, **회전·출발 순간의 노이즈를 감안**해야 한다.
- 정지 구간의 odom은 신뢰도가 높으므로, 정지 기반 검증(ZUPT 등)에 활용 가능.

## CSV 파일 보는 법

`exp2_v2.csv`(및 `exp2_check.csv`)의 odom 행만 사용한다. CSV 구조는 실험 2 문서 참고.

### 분석 (실제 사용)

`analyze_exp4.py`로 저장하고 `PATH`만 바꿔 실행하면 재현된다.

```python
import csv, math, numpy as np

# odom 행만 읽기: t, pos(xyz), quat(xyzw), vel(xyz), angvel(xyz)
# 1) 내부 일관성: v_pos = dp/dt ,  v_twist_world = R_odom·v_twist
#    불일치 = |v_pos − v_twist_world|
# 2) 정지 구간 twist 표준편차 (노이즈 수준)
# 3) 실제가속도 RMS: raw vs smooth (노이즈 비율)
# 4) 구간별 불일치 vs 평균 각속도 (회전 영향)
# 락 검증: 큰 스파이크의 시각(argmax)을 찾고, 락 없는 재측정과 비교
```

### 판정 기준

| 무엇을 보나 | 판정 |
|---|---|
| odom 내부 일관성 | 불일치 평균이 작으면(≤0.1) 대체로 신뢰 |
| 정지 신뢰도 | 정지 시 표준편차 작으면(≤0.01) 믿을 만 |
| 노이즈 비율 | raw RMS ≫ smooth RMS 이면 노이즈 많음 |
| 이상 스파이크 | 시각을 찾아 조작 이벤트(락 등)와 대조 |
